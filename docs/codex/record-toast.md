## Design and plan

Current toast is fixed92px above the bottom safe area. The active dock is fixed
above the navigation with70px content height, so the toast overlays its buttons.
The toast has pointer-events:none: this is text obstruction rather than click
interception. Its existing role/status, polite live announcement, content and
lifetime must remain intact. Target/scoring/storage and stable dock layout stay.

Options considered: a larger fixed CSS offset is simple but guesses dock height;
reserving a new feedback row in the dock consumes small-phone space. Chosen:
measure the current dock's top when notifying and keep16px clearance above it.
The existing offscreen animation translates12px, leaving clearance during entry.
Use a CSS variable scoped to an active record view without a modal. In other tabs
and settings/results overlays, keep the established toast position. A bounded
resize handler updates visible notifications when viewport size changes. Active
view creation also remeasures an already visible notification, so returning from
another tab does not require firing a new notification.

Rendered inspection also found the dark/auto-dark toast background override
replaced the inverse surface with ink while retaining inverse ink text. Measured
contrast was1.107:1 in both engines. Remove that obsolete background override so
foreground/background use the existing paired inverse theme tokens; require4.5:1.
This is the same notification readability scope, not an app-wide theme rewrite.

Vision gates considered: this improves existing score-entry feedback and preserves
the practice-to-analysis loop; no standalone feature or reward. It supports daily
recording and fully local processing. It introduces no growth metric, network,
dependency, fee or private data access. Restrained existing visual tokens remain.
