# 計算の中核の作り直し（2026-11）

画面の構成と保存データの形式はそのままに、採点・グルーピング統計・サイト調整の判定・弾道・サイト予測の
数式を作り直した記録。各節に「旧版の誤り」「新しい式」「根拠と検証」を書く。

## 1. 採点（`scripts/20-scoring.js`）

**旧版の誤り** — 線かみ判定の矢の半径を「的の直径 ÷ 85」としていた。122cm 的では 1.44cm（実際の矢は約 0.28cm）
になり、境界線の外 1.5cm の矢まで高い点になっていた。正規分布の着弾で試算すると 70m・72 射で平均約 13 点、
18m・40cm 的で約 7 点の水増し。さらに境界線の半分の太さを足していた。

**新しい式**

- リングの公称半径 `k·w`（`w` = 的の直径 / 20、フィールドは / 12）を高得点側ゾーンの外縁とする。境界線は
  高得点側に属する（WA 規則）ので線の太さは判定に足さない。的の描画も線を高得点側の内側に収める。
- 矢のシャフトが線に少しでも触れれば高得点: `中心距離 − 矢の半径 ≤ k·w`。
- 矢の半径は的の大きさと無関係な実寸。用具の矢径（mm、3〜10mm）を使い、未入力は 5.7mm。記録開始時に
  `arrowR`（cm）としてセッションに保存する。
- 境界ちょうどの浮動小数誤差（`18.3/6.1 = 3.0000000000000004`）で低い点にならないよう `1e-9` の余裕を持たせる。
- 保存する座標は 0.01cm に丸めるので、丸めた後の座標で採点する。

**表示** — 画面上の矢円は実寸（判定と同じ半径。白い実線の縁の外縁がちょうど判定半径になるよう内側に描く）。122cm 的では 1px 前後になるため、
位置を探すための半透明の目印（白い破線の縁、半径 = 的の直径 / 85）を別に描く。目印は判定に使わない。
微調整モードのレンズは実寸の矢円が見える倍率まで寄せる。

**過去の記録** — 保存された点数は書き換えない。`arrowR` を持たない旧記録は、履歴詳細に
「実寸判定では ◯点（記録時 ◯点・差 ◯点・◯本）」を並べて表示する（`sessionRescore`）。
旧記録の着弾図・編集・更新をまたいで記録途中だった回は、そのセッション内では旧半径（保存された `shaft`、
無ければ旧式）のまま描画・判定する（`sessionScoringRadius`）。保存された点数と矢円が食い違わないようにするため。

**未確認** — フィールド的のリング幅（直径 / 12 の等幅）は WA の図面で確認できていない（本作業では変更なし）。

## 2. グルーピング統計とサイト調整の判定

### 2.1 グルーピング統計（`robustStats`、`scripts/20-scoring.js`）— grouping-v3

詳細な仕様と検証基準は [grouping-stats-v3.md](grouping-stats-v3.md)。

**旧版の誤り** — 中央値/MAD・楕円距離・biweight 重みを経験的な係数で組み合わせた独自方式で、外れ値の除外が矢の記録順で
変わる、重みが u=1 で不連続（u<1 で (1−u²)²、u≥1 で 0.05）、重み付けで RMS が小さく出る、円周上の 6 本で RMS 0.0 を
返す、などの問題があった（旧方式は比較用に `legacyRobustStats` として残し、CSV に出す）。作り直しの途中版で使った
「1 本ずつ除く逐次検定」も、同じ場所にまとまった外れ矢に完全に隠される欠点があった。

**新しい構成**

- **A（正式）全射**: 全部の矢の標本平均・不偏共分散（n−1）、`rr = sqrt(sxx + syy)`、中心の標準誤差と 95% t 区間、
  RMS の 95% 区間（6 本以上、Satterthwaite + Wilson–Hilferty）。表示・推移・成長・今日の結果・CSV の `group_*` はすべて A。
- **B（参考・サイト判断用）外れ値候補を除く**: 決定的な MCD（16 本以下は全列挙、それより多いと固定シードの C ステップ）の
  順位で候補を並べ、1 本除外の厳密 F 検定（`p < 0.01/残り本数`）を Rosner 型に全段実行し、最後に有意だった段までを除く
  （Caroni & Prescott 1992）。何かを除いた時点で小さく出るので補正をかけず参考値とする。サイト判定・個人モデル・回帰・
  サイト中心の履歴は B を使う（外れ矢でサイトを動かさない）。
- **C（参考）ロバスト RMS**: 再重み付け MCD の共分散に一貫性係数（1.859 / 1.104、Croux & Haesbroeck 1999）と
  シミュレーションで作った小標本係数（`tools/gen-mcd-tables.js`）をかけた、まとまっている矢のばらつきの推定。

**検証** — `tools/check-grouping-stats.js`（`check:analysis` に含む）で、A・B・C の偏り、区間の被覆、誤除外率、検出力、
崩壊点、入力順不変、決定性、アフィン不変、縮退、速度、サイト判定の第 1 種の過誤を固定シードのモンテカルロで確かめる。

### 2.2 サイトを動かすかの判定（`sightDecision`、`scripts/40-analysis-physics.js`）

**旧版の誤り** — 「ズレ > max(リング幅/8, RMS×10%)」で動かす判定をしており、本数が入っていなかった。
中心が合っていても 6 本で約 91%、36 本でも約 60% が「動かせ」になった。補正量も信頼度・ポンド・距離などに
根拠のない掛け目（0.45〜1.1）を重ねていた。

**新しい式**

1. 中心のズレを Hotelling T² で同時検定する（2 次元では `F(2, n−2)` の閉じた式）。偶然でこれだけずれる確率
   `p < 5%` のときだけ、さらに軸ごとに 95% 区間がゼロを含まない軸だけを動かす（閉検定。合っている軸を
   巻き添えで動かさない）。
2. 動かす量は軸ごとの縮小推定 `adj = m·max(0, 1 − SE²/m²)`（経験ベイズ。誤差の大きいズレほど控えめ）。
3. 補正量がリング幅の 1/10 未満なら実用上動かさない。
4. 横風（風向と風速が分かるとき）は、風上へねらいを修正したかが記録から分からないため、推定横流れを
   差し引かず、横流れの大きさ全体を左右の誤差に加える（差し引くと、ねらい修正した人に風上へ動かす逆の提案が
   出る）。個人の風係数は、判定中の回と同じ日を除いた 3 回以上の横風の記録があるときだけ使う
   （判定中の回で校正すると係数がその回のズレそのものになり、左右の提案が消える）。
5. mm 換算は `アイ〜サイト距離 × 着弾ズレ / 弾道の感度`（従来どおり）。クリック換算も従来どおり。

動かさないときは「維持」（95% 区間がリング幅の半分以内＝中心が合っていると言える）と「保留」（区間が広く
まだ判定できない → 追加エンド）を区別する。

**検証** — 中心が合っている 6 本の群れで「動かせ」が出る割合は約 5%（旧 91%）。真のズレ 3cm（122cm 的の
半リング）は 12 本で約 5 割、36 本で約 98% 検出する（`tools/check-app.js`）。検定で足切りしない縮小推定のみの
方式も比べたが、中心が合っている場合に 6 本で約半数が平均 2cm 動かしてしまうため採らなかった。

### 2.3 判断信頼度（`sessionQuality`）と個人モデル（`personalModel`）

- 判断信頼度 = グルーピング中心の推定値が真の中心からリング幅の半分以内にある確率（左右 × 上下）。
  標準誤差は `t(0.975, n−1)/1.96` 倍して標本の少なさを補い、ばらつきの下限をリング幅の 1/4 とする。
  旧版は重み付き和に経験的な掛け目を重ねたもので、意味のある量ではなかった。風・外れ値・広さ・本数は理由として
  表示するだけで、数値に掛け目はかけない。
- 個人モデル: 旧版はサイトを動かした前後の着弾中心をそのまま平均していた（サイトを動かせば中心は動くので比較
  できない）。上下・左右のサイト値の記録が今回と同じ（どちらも未記録を含む）同条件の回だけを比べ、回ごとの
  中心は DerSimonian–Laird のランダム効果モデル（回の中の誤差＋日ごとのばらつき）で平均する。回の中の誤差
  だけで重み付けすると、日ごとに中心が揺れる人で過去の傾向を「有意」と誤判定する。
- 回帰（サイト値とズレから「ズレ 0 のサイト値」を推定）の重みも、各回の中心の逆分散に変えた。

## 3. 弾道モデル（`physicsProfile` / `trajectoryModel`）

**旧版の誤り**

- 初速の推定で、パワーストロークに引き尺全体を使っていた（ブレースハイトを無視）。効率も固定。
- 抗力係数（前面積基準）を 1.0〜1.3 とし、細い矢ほど小さくしていた。矢の抗力はシャフト表面の摩擦が支配的で、
  前面積基準の Cd は 長さ/直径 に比例して大きくなる（実測は約 1.5〜2.6）。抗力を過小評価していた。
- 目・矢・的の高低差を入れていなかった。

**新しい式**

- 蓄積エネルギー `E = q × 最大引き重量 × (引き尺 − 1.75inch − ブレースハイト)`、`q = 0.6`。
- 初速 `v = √(2E / (m_矢 + m_仮想))`（Hickman の仮想質量モデル、`m_仮想 = 5.2g`）。弓効率の入力があれば
  `v = √(2·η·E / m_矢)`。40lb・28inch・BH 8.75inch・320gr で約 198fps。実測初速があればそれを使う。
- `Cd = 2.6 × (5.6mm / 矢径) × (矢尺 / 29inch)` に羽根の種類・高さの小さな係数（基準は Park 2011 の
  乱流・ポイント付き実測）。70m で着速は初速の約 88%。
- 発射点は目より 10cm 下、狙う的中心は目より 30cm 下（目の高さ約 1.6m・的中心 1.3m）。

**前提として置いた値（実測で置き換わる）** — `q`、仮想質量、Cd の基準値、目と矢・的の高低差。実測初速、
または 4 距離以上のサイト台帳があれば初速はそちらから決まる。

## 4. 距離別サイト値の予測（`sightInterp`）

**旧版の誤り** — 距離の一次式（4 距離以上で改善すれば二次式）で近似していた。近距離の照準幾何（1/距離 の項）と
空気抵抗による曲がりを表せず、実測範囲の外への予測が 2〜9mm ずれた。

**新しい式** — 弾道から、矢の発射方向と照準線（目→的中心）の角度差 α を距離ごとに計算し、サイト値を
`s = a + b·tan(α)` と線形回帰する（a は目盛りの原点、b は目盛りの単位と向き。アイ〜サイト距離も b に吸収）。
5 距離以上の台帳で、初速を加えた改善が入れ子モデルの F 検定（5%）で有意な場合だけ、初速も黄金分割探索で当てはめる
（4 距離では自由度 1 で不安定、探索範囲の端に張り付いた値は採らない。実測初速の入力があれば固定）。

**検証** — 前提と異なる「真の値」（目と矢の高低差 12cm、的との高低差 25cm、Cd 2.0、初速 58m/s）と
0.2mm の記録誤差で作った台帳に対し、予測誤差は 0.2〜1.4mm（旧版の近似は 0.4〜9.2mm）。
`tools/check-app.js` に固定の検証を置いた。

## 5. 検証の経緯

独立レビュー（コードを読み、シミュレーションで確認）で次の指摘を受けて修正した: 判定中の回を含む風係数で
左右の提案が消える／推定横流れの差し引きでねらい修正した人に逆向きの提案／合っている軸の巻き添え／個人モデルが
日ごとのばらつきを無視／旧記録の着弾図が保存点数と食い違う／4 点での初速当てはめが不安定／白縁が判定半径から
はみ出す／2 本で判断信頼度 100%／物理側の矢径の範囲チェック漏れ。採点は 120 万点の総当たり（円が触れる最も
高いゾーン）と 0 件の不一致、統計は誤警報 5.0〜5.6%・誤除外 0.9〜1.1%・95% 区間の被覆 94.7〜95.1% を確認した。
