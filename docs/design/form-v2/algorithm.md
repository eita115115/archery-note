## 1. 契約

```text
FormAnalyze.analyze(frames, { frame: { w, h }, handedness, fps }) → { shots, candidates, quality }

frames      = [{ tMs, landmarks: [33 × { x, y, z, visibility }] | null }]
              tMs は撮影開始からの ms。x, y は MediaPipe の正規化座標（x は幅、y は高さで割った値、y は下向き）。
              landmarks が null のコマは「姿勢が取れなかった」。
frame.w, h  = ランドマークを正規化した画面の大きさ（px）。縦向きなら w < h。
handedness  = "right" | "left"（right = 右手で引く。弓は左手）
fps         = 目安の値。時刻は tMs だけを信じる（間隔が不ぞろいでもよい）。

shots       = [{ releaseMs, anchorStartMs, holdMs, kind: "shot" | "letdown", features, ...追加の項目 }]
              時刻の昇順。射数は kind === "shot" の個数。**離れの位置がはっきり決まった射だけ** が入る。
candidates  = [{ tMs, uncMs, reason, likely, fromMs, toMs, templateDist? }]
              引いて保持したが、離れの位置がはっきりしなかったもの。射数には入れない。
quality     = この回の測定の質（6 章）
```

**数えるもの・数えないもの**（オーナーの決定、2026-11-14）: 離れの位置がはっきり決まらなかった射は、数に入れない。
`shots` とは別に `candidates` で返し、結果の画面の「射数を直す」で、利用者が射として足せるようにする。下書きにあった
`weak: true`（数には入れるが時刻は粗い射）は無くした。解析器が「射」と言うのは、離れの時刻に自信があるときだけである。

`shots` の追加の項目（契約を壊さない範囲で足す）:

| 項目                    | 意味                                                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `drawStartMs`, `drawMs` | 引き始めの時刻と、引き始めからアンカーまでの時間                                                                   |
| `drawEndMs`             | 引きの動きが終わった時刻（4.8 の当てはめ。当てはめられなかった射は `anchorStartMs` と同じ）。`anchorFit` がその印  |
| `releaseUncMs`          | 離れの時刻の不確かさ（ms）。ふつうは 1コマの 1/4、肘で決めたときは 40 以上、追跡の途切れにかかれば途切れの幅の半分 |
| `confidence`            | 0.5〜1（射）。離れの段差が、保持のゆれの幅の何倍あったか（`kindScore`）から決める。引き戻しは 0.8                  |
| `source`                | 離れを見つけた手がかり: `"draw"`（引き手の手首）/ `"elbow"`（手首が見えず、引き手の肘）                            |
| `kindScore`             | 離れの段差の大きさ（保持のゆれの幅の何倍か。4.6 の `zL`）                                                          |
| `features`              | 射ごとの値（5 章）。測れなかった項目は null                                                                        |
| `wins`                  | 項目ごとの、保持の中の窓の中央値の列（測定のゆれの見積もりに使う。保存しない）                                     |
| `poseHold`, `poseRel`   | 重ね図用の姿（5.5）。9 点 × (x, y) の整数の列（0.01 胴）。`poseRel` は射だけ（引き戻しは null）                    |
| `typicality`            | その回の型（4.9）からの遠さ（1 以上は型から遠い）。はっきりした射が 3 本未満の回は付かない                         |

`kind === "letdown"` の行は `releaseMs` に「保持が終わって手が前へ動き始めた時刻」を入れる。`features` は同じ形で返すが、
射どうしの比較には使わない。

`candidates` の項目:

| 項目             | 意味                                                                                                                                                                                                                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `tMs`, `uncMs`   | 離れがあったとすればこのあたり、という時刻とその不確かさ（150 または 500）。画面で動画の位置を出すのに使う                                                                                                                                                                                 |
| `reason`         | `"weakRelease"`（段差はあるが、はっきりしない）/ `"noRelease"`（腕は下ろしたが、段差が見つからない）/ `"unobserved"`（保持の途中で見えなくなった）/ `"bodyMoved"`（同じ時刻に頭や胴が大きく動いた）/ `"short"`（止まってから終わりまでが短すぎる）/ `"tooSoon"`（前の事象から 1.5 秒以内） |
| `likely`         | true = その回のはっきりした射の型（4.9）によく似ている。画面では「射かもしれません」として先に出す                                                                                                                                                                                         |
| `fromMs`, `toMs` | 引いていた区間                                                                                                                                                                                                                                                                             |

決まりごと:

- 純関数。DOM・`db`・時計・乱数を使わない。同じ入力には同じ出力。入力の配列を書き換えない。
- 入力が空・短い（10コマ未満）・体が写っていないときは `shots: []`・`candidates: []` と `quality.warnings` を返す。例外は投げない。
- 画面の形・左右・大きさ・時刻の原点を変えても結果が変わらない（7.4 の不変性の検査）。
- 単位は「胴の長さ」（両肩の中点から両腰の中点まで）。cm への直し方は 5.6（解析器の中には持たない）。

内部の関数（どれも純関数。`FormAnalyze.*` で Node から単体の検査ができる）:


## 2. なぜ「あとでまとめて」か

いまの仕組みは、1コマごとに状態を進める実時間の状態機械で、しきい値はすべて手で決めた固定値である。
監査（AUDIT.md）にある失敗は、ほぼこの作りから出ている。

| いまの失敗                                       | 原因                                                  | まとめて解析すると                                                                             |
| ------------------------------------------------ | ----------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 縦向きで 0射（アンカー圏に入らない）             | 画面の形に依存する固定のしきい値                      | 画素で測り、胴の長さで割る。しきい値はその回の分布から決める                                   |
| 6射のうち 4射を落とす                            | 発射の速さ 9 胴/秒 に届かない、保持の条件を満たさない | 先に「手を前へ戻さずに腕を下ろした」ことで射と決め、離れの位置はその保持自身のゆれと比べて探す |
| 16 回の発射のうち 13 回を捨てる                  | 発射のあと 400ms で取り消しを決める                   | 離れのあと 0.5 秒以上の動きまで見てから、射か引き戻しかを決める                                |
| 引き切りの肘の角度が 125° を超えない             | 画像の上の角度を、立体の角度のつもりで門にしていた    | 肘の角度を門に使わない。使うのは手首・肩・鼻の位置だけ                                         |
| ドリフトのしきい値がランドマークのゆれより小さい | ゆれを測っていない                                    | 回ごとに測定のゆれを見積もり、それより大きい違いだけを出す                                     |
| 追跡が切れると橋渡しの特例（NB/NB2）が要る       | 先が見えないので、その場で決めるしかない              | 欠測の前後を両方見て、短い欠測は補間、長い欠測は「見えなかった」として扱う                     |

実時間で要るのは、置き方の案内と、撮影中のおおよその射数だけになる。射数は、同じ解析器を直近 20 秒に 1 秒おきに
かけて出す（別の状態機械を持たない）。終わったあとの解析が正で、撮影中の数は「目安」と明記する。

検討して採らなかった案:

- **動画を丸ごと取っておき、あとで全コマを推論する**: 60fps の全コマと重いモデルが使えるが、10 分の動画（約 190MB）を
  メモリに持ち、推論に数分かかる。射場で待てない。保存済み動画の解析（撮影とは別の入口）にだけ使う。
- **学習済みの分類器で射を見分ける**: 実射の教師データが無く、オーナーの映像を fixture にしない方針とも合わない。
- **MediaPipe の z（奥行き）を使う**: 1台のカメラからの推定で、手首の z は誤差が大きい。検出にも特徴にも使わない。

## 3. 座標と信号

### 3.1 取り込み（`packFrames`、`repairSwaps`）

- 時刻順に並べ、同じか戻る時刻のコマは捨てる。
- 使う点は 9 つ: 鼻(0)、肩(11, 12)、肘(13, 14)、手首(15, 16)、腰(23, 24)。残りは読まない
  （耳 7, 8 と膝 25, 26 は予備。10.1 のメモリの見積もりには入れてある）。
- 点を使う条件: 値が有限、`visibility ≥ V_MIN (0.3)`、x と y が −0.2〜1.2。満たさない点は欠測（NaN）。`visibility` の値そのものは
  別に持っておく（3.3 の「隠れ」の判定に使う）。
- **正方形の画素にする**: `X = x·w`、`Y = y·h`。以後、距離と角度はすべてこの座標で測る。
  段A の「16:9 の基準座標」は検出のしきい値を動かさないための選択だったので、v2 では使わない。
- **利き手**: 右利きは 弓手 = 左(11, 13, 15, 23)・引き手 = 右(12, 14, 16, 24)。左利きは入れ替える。
- `coverage` = 姿勢が取れたコマの割合。
- **左右の入れ替わりを戻す**（`repairSwaps`）: 姿勢推定は、1〜数コマだけ腕の左右を取り違えることがある。手首が 1 コマで
  `SWAP_JUMP (0.5)` 胴以上跳んだコマから `SWAP_MAX_FRAMES (8)` コマについて、前後 `SWAP_REF_MS (700)` の中央値の姿と比べ、
  肩・肘・手首の左右を入れ替えたほうが半分以下の距離になるコマだけを入れ替える。入力は書き換えない（写しを作る）。
  戻した数は `quality.repaired.swapped`。

### 3.2 等間隔にする（`resample`）

- 間隔 `dt` = コマ間隔の中央値（1000/60〜100ms に収める）。時刻 `t0 + g·dt` の格子へ、点ごと・軸ごとに線形補間する。
- 前後の有効な標本の間が `GAP_FILL_MS (200)` 以下（かつ 1.5·dt 以上のときはその値）なら補間し、それより長ければ欠測（NaN）のまま。
  補間した標本には、前後の標本の間隔（`span`）を覚えておく（離れの時刻の不確かさに使う。4.6）。
- 撮影中に推論の間隔を変えても（10.3）、ここで同じ間隔になる。

### 3.3 体の単位（`buildSignals`）

1. **隠れた点を外す**: 両手首について、その点のふだんの `visibility`（前後 3 秒の中央値）から
   `max(VIS_DIP_MIN (0.15), VIS_DIP_K (3) × ゆれ)` 以上落ちたコマ（と、その前後 1 標本）を欠測にする。顔や弓に隠れた手首は、
   `visibility` が下がると同時に位置もずれる（顔・肘のほうへ寄る）ので、位置だけを見ても見分けられないからである。
   肘には使わない（離れのあとに腕が体に重なると、`visibility` の水準そのものが変わる）。
2. 外れ点の除去: 各座標に Hampel フィルタ（前後 `HAMPEL_HALF (2)` 標本、中央値から `HAMPEL_K (3)` × MAD を超えたら中央値に置き換える）。
   1コマだけ跳ぶ点を消し、段差（離れ）は残す。**これが「事象用」の系列**で、これ以上は平滑しない。特徴（5 章）と離れの時刻はこの系列から取る。
3. 胴の長さ `T(t)` = 両肩の中点と両腰の中点の距離（px）を、幅 `SCALE_WIN_MS (2000)` の移動中央値にしたもの。取れないコマは回全体の中央値 `T0`。
   コマごとの値で割ると、肩と腰のゆれがすべての値に乗る（いまの仕組みの問題）。2 秒の中央値なら、立つ位置が変わったときだけ追従する。
4. **人の入れ替わり**: 腰の中点が `IDENTITY_MS (200)` 以内に `IDENTITY_JUMP (1.0)` 胴以上動いた所に「切れ目」を入れる。
   引いている区間（4.3）は切れ目をまたがず、アンカー（4.8）も切れ目より前へさかのぼらない。
5. 弓の向き `dir` = 「弓手の手首 − 引き手の肩」の x の中央値の符号（0.6·T0 より離れているコマだけ）。+1 なら弓は画面の右。
6. **正準座標**: 原点 = 両肩の中点、x = `dir·(X − 肩中点X)/T`（弓の向きが正）、y = `−(Y − 肩中点Y)/T`（上が正）。単位は「胴の長さ」。
   左利き・背中側からの撮影は、ここで右利き・胸側と同じ形になる。体ごとの動き（重心のゆれ、カメラのゆれ）は原点と一緒に消える。
7. **補完（検出にだけ使う）**: 手首が欠測で肘が見えているコマは、手首 = 肘 + 「引いているときの 肘 → 手首 のベクトル」の中央値 とする
   （引き手・弓手とも）。鼻が見えないコマは、鼻の高さ = 回全体の中央値。補完した点は、引いている区間・終わり方・アンカーの判定に
   だけ使い、**特徴と離れの時刻には使わない**。補完したコマの数は `quality.repaired.imputedDraw`・`imputedBow`。
8. 信号（どれも胴の長さの単位）:

| 記号         | 定義                                                                             | 使いみち                           |
| ------------ | -------------------------------------------------------------------------------- | ---------------------------------- |
| `d`          | 弓手の手首と引き手の手首の距離（事象用。補完なし）                               | 特徴（引き尺の目安）               |
| `ds`         | 同じ距離を、補完した手首で作って平滑したもの                                     | 引いている区間、引き戻し           |
| `es`, `ees`  | 弓手の手首（補完あり）・弓手の肘の高さ − 弓手の肩の高さ（平滑）                  | 弓を上げているか、腕を下ろしたか   |
| `ays`, `axs` | 引き手の手首（補完あり）の高さ − 鼻の高さ、x − 鼻の x（平滑）                    | 引き手が顔の所にあるか             |
| `ps`, `vs`   | 引き手の手首（補完あり）の位置の平滑と、その速さ（前後 1 標本の中心差分、胴/秒） | 手が止まったか、アンカー           |
| `C.*`        | 9 点の正準座標（事象用）                                                         | 離れの位置と時刻、特徴、重ね図の姿 |

平滑は、幅 `SMOOTH_MED_MS (100)` の中央値 → 幅 `SMOOTH_AVG_MS (160)` の平均（前後対称なので時刻がずれない）。
平滑を 2 本に分ける理由: 時刻は平滑でなまる（160ms の平均は段差を 160ms に広げる）。区間の判定は平滑した系列で、
時刻は事象用の系列で決める。

## 4. 射と引き戻しを見つける

### 4.1 考え方

射の 1 周期は、1 本の信号 `d`（手首どうしの距離）に大きく出る。セットアップで約 0.4、引き切りで約 1.4〜1.6（真横）、
つまり雑音（0.01〜0.1）の十数倍以上の振れ幅がある。引き切りの水準は同じ射手なら毎回ほぼ同じなので、
**その回の分布から水準を決められる**。

保持の終わり方は 2 つしかない。

- **離れ**: 引き手が後ろ（弓と反対の向き）へ急に動き、肘も一緒に動く。手首どうしは近づかない。そのあと腕を下ろす。
- **引き戻し**: 引き手が前（弓の向き）へ戻り、手首どうしが近づく。弓は上げたままのことも、一緒に下ろすこともある。

速さの大きさは使わない。使うのは **手首どうしが近づいたか**・**弓手が下がったか**（終わり方）と、引き手の腕が保持の位置から
**動いたまま戻らない** こと（離れの位置）で、どれも置き方に依らず符号が変わらない。順番は「終わり方を先に決め、離れの位置をあとで探す」。

離れの位置を探すのに「いちばん大きく動いた瞬間」を使わないのが、下書きとの大きな違いである。独立したベンチマークのゆれ
（手首の位置が 0.3〜1 秒かけて胴の 5〜10% ずれて戻る）の下では、保持の途中のゆれが離れの段差（胴の 25〜40%）の半分近くに
なる瞬間があり、最大の瞬間を取ると 3 割を取り違えた（7.2.1 の下書きの行）。**離れのあと、腕を下ろし始めるまで、手は保持の位置へ
戻らない。保持の途中のゆれは戻る。** これを使う（4.6）。

### 4.2 構えの門（置き方に強い 3 条件）

```text
G1: G1_LO (−0.45) ≤ es  ≤ G1_HI (+0.7)     弓手の手首が、弓手の肩とほぼ同じ高さ（長距離の仰角を許す）
G2: G2_LO (−0.65) ≤ ays ≤ G2_HI (+0.3)     引き手の手首が、鼻より少し下〜顔の高さ
G3: G3_LO (−1.1)  ≤ axs ≤ G3_HI (+0.25)    引き手の手首が、鼻の少し前〜後ろ（顔まで引いてきた。腕を後ろへ伸ばしきってはいない）
```

G1・G2 は **高さだけ** の条件である。カメラが斜めでも、縦の長さはほとんど縮まない（横の長さは cos で縮む）ので、置き方で変わりにくい。
G3 は横の条件だが、符号と大まかな範囲しか見ないので、斜めでも（縮むだけで）成り立つ。G3 の上限は、セットアップ（引き手が弓の近くにある）を
引いている区間から外すために入れた。上限が無い版は、独立したベンチマークの 1 回で保持の水準をセットアップに取り違えた。
下限は、両腕を広げるストレッチを外すためのもの（射のない場面で 1 回、射に数えた）。
矢取り、弓を持って歩く、弓を片手で上げる、といった場面は、どれかを満たさない。

### 4.3 保持の水準と、引いている区間（`holdLevel`、`drawnRuns`）

1. G1〜G3 を満たし、引き手が止まっている（`vs < still`。4.4）コマの `ds` を集める。止まっている所は、保持と離れのあとの残身にかたまる。
2. 幅 `LEVEL_BIN (0.05)` のヒストグラムで、隣り合う 3 つの合計が極大になる所を「かたまり」とする。使うのは、いちばん大きい
   かたまりの `LEVEL_MASS (25%)` 以上の時間があり、250ms 以上で、`D_MIN (0.55)` 以上のものだけ。
3. **保持の水準 `level`** = いちばん高いかたまりの `LEVEL_REL (0.55)` 倍以上で、いちばん低いかたまりの中央値。
   残身は保持より引き尺が長い。該当が無ければ射なし（`warnings: "noFullDraw"`）。
4. しきい値 = `max(D_MIN, D_FRAC (0.8) × level)`。G1〜G3 を満たし `ds` がしきい値以上のコマの連なりを区間とする。
   途切れは `RUN_BRIDGE_MS (700)` まで橋渡しし、`RUN_MIN_MS (300)` より短い区間は捨てる。切れ目（3.3 の 4）はまたがない。区間には残身も入る。
5. 弓手を上げたまま（区間の間の `es` の中央値が G1 の中）、`RUN_JOIN_MS (1500)` 以下の間をおいて続く区間は、1 つにつなぐ。
   引き手のゆれや隠れで区間が切れただけで、保持は続いているからである（つながない版は、引きの途中を射に数えた）。

`D_MIN` の 0.55 は「手首どうしが胴の長さの半分強は離れている」という意味で、真横なら引き切りの 4 割、50° 斜めでも 6 割にあたる。

### 4.4 手が止まった位置

- 静止の速さ `still` = `clamp(STILL_K (3) × vs の 20% 点, STILL_MIN (0.2), STILL_MAX (0.8))` 胴/秒。
  ランドマークのゆれが大きい回は自動で上がる。下限 0.2 は、胴 50cm なら 10cm/秒。
- 区間の中で、`ds` が保持の水準の `SETTLE_FRAC (0.93)` 倍に届いていて、`vs < still` が `SETTLE_MS (150)` 続いた最初の位置を
  「手が止まった」とする。無ければ区間の先頭。水準の条件は、ゆっくりした引きの終わりを「止まった」と取り違えないため。
- 離れは、そこから `PRE_MIN_MS + PRE_TO_MS (210ms)` あとより先で探す。**保持が 0.2〜0.4 秒より短い射（速射）は、保持の位置が
  決まらないので、離れをはっきりとは決められず、ほとんどが候補になる**（7.2.4 の rapid-fire）。

### 4.5 終わり方を、大きな動きで決める（`runEvent` の前半）

止まった位置から、区間の終わり + `LOOK_MS (2500)`（次の区間の手前まで）へ向かって、最初に起きたものを取る。

| 起きたこと                                                              | 種類      |
| ----------------------------------------------------------------------- | --------- |
| 手首どうしが近づいた（`ds ≤ D0 − closeTh`）とき、弓手はまだ上がっている | `"close"` |
| 弓手が下がった（下の「下がり」が 1 以上）。近づくのと同時でもこちら     | `"lower"` |
| `RUN_BRIDGE_MS` を超えて見えなくなった、または切れ目に当たった          | `"gap"`   |
| どれも起きないまま終わった                                              | `"end"`   |

```text
D0, e0, ee0 = 止まってから HOLD0_MS (1000) の ds・es・ees の中央値
closeTh = max(CLOSE_FRAC (0.3) × D0, MACRO_K (5) × ds のゆれ)
dropTh  = max(ARM_DROP (0.45),       MACRO_K (5) × es のゆれ)
下がり  = 手首: (e0 − es) / dropTh、 肘: (ee0 − ees) / ELBOW_DROP (0.25)。両方見えていれば平均、片方だけならその値
どれも、その時点から SUSTAIN_MS (300) の中央値でも超えていること
```

下書きは `CLOSE_FRAC 0.12`・`ARM_DROP 0.15` で、弓手の手首だけを見ていた。弓手の手首は弓に隠れてゆれが大きく（独立したベンチマークで
高さの標準偏差が胴の 8%、弓に隠れる場面ではその 2〜3 倍）、保持の途中や離れの直後に「下がった」と取り違えた。腕を下ろす動きは
胴の長さほどの大きな動きなので、しきい値を大きくし、ゆれの小さい肘も使う。肘は手首の半分ほど下がるので、しきい値も半分強にしてある。

**腕を下ろし始めた所 `to`**: `"lower"` のときは、その時刻から最長 `ONSET_BACK_MS (1200)` さかのぼり、「下がり」が直前の水準
（1.3〜0.5 秒前の中央値）+ `ARM_ONSET (0.27)` 以下だった最後の位置。`"close"` のときは、`ds` が `D0 − closeTh/3` を下回り始めた所から
`CLOSE_GUARD_MS (150)` 手前。離れは `to` より前にある（腕を下ろす動きそのものを離れと取り違えない）。

### 4.6 離れの位置と時刻（`changePoint`、`jumpAt`、`onsetFit`）

**変わり目を 1 つ探す**（`changePoint`）。保持 `[止まった位置, 終わり]` の中で、「これより前は保持の位置 A の近く、あとは
終わりぎわの位置 B の近く」がいちばんよく当てはまる時刻 `c` を、累積和で求める。

```text
使う点: 引き手の手首と肘（事象用の系列。2 次元の位置のまま）
A = 保持の位置（最初は、始めから CP_HEAD_FRAC (40%) の中央値）、 B = 終わりぎわの位置（最初は、to の前 CP_TAIL_MS (400) の中央値）
σ = その点のゆれの幅（A からの距離の中央値 / 1.177。下限 STEP_NOISE_MIN (0.004)）
1 コマの寄与 llr(t) = Σ_点 ( |x(t) − B| − |x(t) − A| ) / σ          A に近ければ正、B に近ければ負。見えないコマは 0
S(c) = Σ_{t < c} llr(t) が最大になる c が変わり目
c が決まったら、A = c の前 [CP_SEG_MS (1500), PRE_TO_MS (60)]、B = c のあと [POST_FROM_MS (80), CP_SEG_MS] の中央値に取り直して、もう 2 回まで繰り返す
終わり = 腕を下ろして終わったなら min(下ろした時刻, to + LOWER_TAIL_MS (200))（離れてすぐ腕を下ろす人のため）、ほかは to
```

- 1 コマの寄与は A–B の距離を超えない（三角不等式）ので、一時的な取り違え（顔の前で手首の点が跳ぶ、肘が裏返る）は、
  続いた時間ぶんしか効かない。保持の途中のゆれで B のほうへ寄っても、戻れば累積和は元の伸びに戻り、`c` は動かない。
- 手首が見えないコマは肘だけ、肘が見えないコマは手首だけで決まる。どちらも段差が無ければ（A ≈ B）、寄与はほぼ 0 になる。
- 計算は保持 1 つにつき O(コマ数)。

**はっきりした離れかどうか**を、変わり目の 2 つの量で決める。

```text
段差   stepW = (B − A)·û（引き手の手首。引きの軸 û = 保持の始めの 弓手の手首 → 引き手の手首。後ろが正）、 stepE = |B − A|（引き手の肘）
zL = hypot( max(0, stepW/σ_手首), max(0, stepE/σ_肘) )                          保持の位置から動いたまま、という証拠
急な動き jW, jE = 変わり目の前後 [JUMP_NEAR (50), JUMP_FAR (220)] ms の中央値の差（手首は û へ射影、肘は距離）
zJ = hypot( max(0, (jW − 中央)/幅), max(0, (jE − 中央)/幅) )                    中央・幅 = 同じ量を、変わり目より前の保持の中で測った分布の中心と幅
後ろ = stepW ≥ EXIT_MIN (0.05)、または jW ≥ EXIT_MIN かつ その z ≥ LOCATE_J かつ stepW > −EXIT_MIN（手首が見えないときは stepE ≥ EXIT_MIN）
```

分布の中心と幅は、全体の `SHORTH_FRAC (35%)` を含むいちばん短い区間（shorth）から取る。離れそのものが分布に混じっても、
保持のゆれのかたまりを取り出せる（中央値と分位点から取る版は、保持が短いとき離れの段差に引きずられた）。

| 終わり方          | 条件                                                                                                               | 結果                                                                              |
| ----------------- | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| どれでも          | 変わり目の前後で、鼻か腰が `BODY_JUMP (0.2)` 以上動いた、または胴の長さが 15% 変わった                             | 射に数えない。候補 `"bodyMoved"`（人や場面の切り替わり、姿勢推定の取り違え）      |
| lower             | 後ろ、`zL ≥ LOCATE_K (5)`、かつ（`zJ ≥ LOCATE_J (2.5)` または `zL ≥ EXIT_K (6)`）、`c < to − LOWER_GUARD_MS (150)` | **射**                                                                            |
| close / end / gap | 後ろ、`zL ≥ EXIT_K (6)`、`zJ ≥ EXIT_J (4)`                                                                         | **射**（離れのあと、弓手を上げたまま引き手を下ろした、など）                      |
| close             | 上を満たさない                                                                                                     | **引き戻し**。時刻は `ds` が下がり始めた所（`releaseUncMs = 150`）                |
| lower             | 上を満たさず、腕を下ろした時点で引き手が保持位置より `LETDOWN_FWD (0.25)` 以上前にある                             | **引き戻し**（弓を下ろしながら弦を戻した）                                        |
| lower             | どちらでもない                                                                                                     | 射に数えない。候補 `"weakRelease"`（後ろ、`zL ≥ LOCATE_K/2`）または `"noRelease"` |
| end / gap         | 上を満たさない                                                                                                     | 射に数えない。候補 `"noRelease"` / `"unobserved"`                                 |

腕を下ろして終わった保持は、それだけで射の証拠になる（手を前へ戻していない）ので、しきい値を低くしてある。それでも、離れの位置が
はっきりしなければ数えない（1 章）。`LOCATE_K` は、独立したベンチマークで 3・4・4.5・5・6 を比べて 5 にした（8 つの種、全場面）:
3 だと、離れが弱い場面と速射で「自信を持って間違えた射」が 7 本あり、5 で 1 本になる。代わりに、ふつうの場面の射の 0.8% が候補へ回る。

**変わり目が、腕を下ろし始めた所と重なるとき**（`c ≥ to − 150ms`）は、下ろす動きそのものを拾っているので、離れとは認めない。
離れてすぐ腕を下ろす人では、離れが `to` の 0.3 秒ほど前に来るので拾える（7.2.1 の drop-arm は 30 射のうち 26 射）。

**動き始めの時刻**（1コマより細かく、`onsetFit`）: `c` は「A と B の中ほどを越えたあとの最初のコマ」なので、動き始めはその少し前にある。
A から B へ向かう変位（0〜1 に直したもの）に、「止まっていた手に、ある時刻から力がかかる」形を当てはめる。

```text
u(t) ≈ 0                                   (t < tr)
       1 − (1 + s)·e^(−s),  s = (t − tr)/τ  (t ≥ tr)        臨界減衰の 2 次の応答
tr を dt/8 刻みで [c の 1 コマ前 − FIT_EARLY_MS (100), c]、τ を FIT_TAUS (15, 25, 35, 50, 70 ms) から選び、
[c − FIT_BEFORE_MS (350), c + FIT_AFTER_MS (300)] の残差二乗和が最小の組
τ は、残差が最小の 2 倍以内の候補の中では FIT_TAU_TYP (30) に近いものを取る（コマの間隔が粗いと τ は決まらないため）
```

- 形を直線の立ち上がりから変えた理由: 実際の動きは速さ 0 から始まるので、直線を当てはめた動き始めは遅く出る（検査用の合成で 60fps のとき +17ms）。
  離れは、弦の力が急にかからなくなって手が動き出す動きなので、力がかかり始める形のほうが近い。ただし **これは仮定である**
  （独立したベンチマークの離れも同じ形で作られている。検査用の合成 `tools/form-analyze-fixture.js` は、わざと別の形 — 最小躍度 70ms — にしてある）。
- 時刻は引き手の手首で決める。動き始めの所で手首が写っていなければ肘で決め、`releaseUncMs` を `ELBOW_UNC_MS (40)` 以上にする。
- 手首も肘も写っていない（追跡が切れた、`GAP_MIN_MS (100)` 以上）なら、動き始めはその欠測の中にある。追跡は離れの速い動きで
  切れることが多いので、時刻は欠測の始まり + `min(幅/2, GAP_ONSET_MS (40))` に置き、`releaseUncMs` = 欠測の幅の半分。
- ふつうは `releaseUncMs = dt/4`。

事象どうしは `REFRACTORY_MS (1500)` 以上あける（矢をつがえて引くまでに数秒かかる）。同じ区間で事象は 1 つ。

捨てた版（どれも独立したベンチマークで試した。数値は 7.2.1）:

- 下書き: 「直後の窓 − 直前の窓」が最大の瞬間を取る。保持の途中のゆれ・顔の前での取り違えを離れと取り違えた。
- 上に、「あとの窓でも動いたままか」の確認と、肘を足したもの。再現率は 0.78 止まり。段差の統計のゆれの幅が、離れを含む分布から
  取られて大きくなり、はっきりした離れが 3〜4σ にしか見えなかった。
- 変わり目だけで決める（急な動き `zJ` を見ない）: 保持の中のゆっくりしたずれを離れに数える恐れがあるので採らなかった。

### 4.7 追跡が切れたとき・点が隠れたとき

- 200ms 以下の欠測は補間ずみ。変わり目の探し方（4.6）は見えないコマを飛ばすだけなので、補間できない長さの欠測も、
  `RUN_BRIDGE_MS (700)` までは保持をまたいで続けて見る。
- 離れの所で追跡が切れた: 変わり目は欠測の終わりに出る。時刻は 4.6 の決まりで欠測の始まり寄りに置き、不確かさを広げる。
  独立したベンチマークの release-dropout（7 割の射で 80〜350ms 切れる）で 30 射のうち 29 射を数え、時刻の 90% は 57ms だった。
- 保持の途中から、手首が弓や腕や顔に隠れる: 3.3 の 1（`visibility` が落ちたコマを外す）と 7（肘からの補完）で扱う。
  引いている区間は補完した手首で続き、離れは肘でも拾える。
- 終わり方が `"gap"`・`"end"` で離れが見つからないとき: `candidates` に残す（`"unobserved"`・`"noRelease"`）。射には数えない。
- 人が入れ替わった・横切った・場面が変わった: 3.3 の 4（切れ目）と、4.6 の `"bodyMoved"`。素材映像の 1 本（場面が溶け合って
  切り替わる編集）で、切り替わりを離れに数えたために入れた（7.2.5）。
- 左右の入れ替わり: 3.1。

### 4.8 アンカーに入った時刻と引き始め（`anchorStart`、`fitDraw`）

定義: **アンカーに入った時刻 = 引き終わりに、引き手の速さが `STILL_MIN`（0.2 胴/秒）を下回り続けた最初の時刻**（「手が止まった」）。
独立したベンチマークは、この定義の正解（`anchorStillMs`）と、引きの動きが終わった時刻の正解（`anchorMs`）の両方を持っている。

速さを差分で測ると、ランドマークのゆれに負ける（独立したベンチマークのゆれでは、差分の速さのゆれが 0.3〜0.7 胴/秒ある）。
そこで、引きの軌道に滑らかな形を当てはめ、その形の上で速さを見る。

1. 引きの進み具合 `w(t)` = 引き手の手首（補完あり・平滑）の、引きの軸 û に沿った位置。`d` より雑音が小さい（弓手の手首のゆれが入らない）。
2. **境目**（`anchorStart`）: 離れからさかのぼり、「ここから先は、`w` が保持の水準の近くにある」がいちばんよく当てはまる時刻を累積和で取る。
   水準は「引く前（止まった位置の前 4 秒の最小値）→ 保持（止まった位置から離れまでの中央値）」の `ANCHOR_LEVEL (85%)`。
   保持の途中のゆれでは境目は動かない。切れ目より前へはさかのぼらない。
3. **形の当てはめ**（`fitDraw`）: `w` が「引く前の水準 → 最小躍度の立ち上がり（Flash & Hogan 1985）→ 保持の水準」をたどるとして、
   引き始め `t0` と引き終わり `t1` を、残差の二乗和が最小になるように選ぶ（粗く 100ms 刻み → 細かく 25ms 刻み）。
   引く前の水準は、引き始めの直前 `DRAW_BASE_MS (400)` の中央値。
4. 当てはまりがよければ（残差の RMS ≤ 振れ幅の `DRAW_FIT_RMS (12%)`）、`drawStartMs = t0`、`drawEndMs = t1`、
   `anchorStartMs` = 当てはめた形の速さが `STILL_MIN` を下回る時刻（`t1` の 0.1〜0.4 秒前）。
5. 当てはまらなければ、境目から先で `vs < still` が `SETTLE_MS (150)` 続いた最初の時刻（`SETTLE_WAIT_MS (400)` まで。無ければ境目）を
   アンカーとし、引き始めは `ds` が「直前 4 秒の最小値 + 15%」を下回る最後の時刻。`anchorFit: false`。

最小躍度の形は、止まった所から止まった所への随意運動のよく知られた近似だが、実際の引きがこの形とは限らない
（アンカーの手前で一度止まる人、ゆっくり伸び合う人）。そのときは 5 へ落ちる。**どちらにしても、保持の長さは「定義」と「形の仮定」で
0.1〜0.4 秒変わる量である**。同じ射手の回の中で比べるぶんには、ずれは一定に近い。

結果（7.2.3）: 雑音なしなら、保持の長さの誤差は中央値 14ms・95% で 39ms。独立したベンチマークのゆれの下では中央値 0.11 秒・90% で 0.32 秒・
95% で 0.47 秒で、7.4 の基準（95% で 0.22 秒）には届かない。

### 4.9 自己相似: その回の「型」と比べる（`templateMatch`）

はっきりした射が `TPL_MIN_SHOTS (3)` 本以上あるとき、その回の「型」を作って、候補を見直す。

1. 型 = はっきりした射の、離れの前 `TPL_BEFORE_MS (2000)`〜後 `TPL_AFTER_MS (600)` の `ds / 保持の ds`・`es − 保持の es`・`ays − 保持の ays` の、
   時刻ごとの中央値（保持の値は、離れの [600, 60] ms 前の中央値）。
2. 射から型までの距離 = 項目ごとの差の絶対値の平均を、「その射を抜いて作った型からの距離」の中央値で割り、3 項目で平均したもの。
3. 候補（腕を下ろして終わった保持）は、型を 1 標本ずつずらしながら当て、見えている標本が `TPL_COVER (50%)` 以上ある位置の中で
   いちばん近い距離を取る。それが「はっきりした射を 1 本ずつ抜いて測った距離の最大 × `TPL_BOUND (1.5)`」以下なら、
   候補に **`likely: true`** を付ける。離れの見当が無い候補（`"noRelease"` など）は、時刻を型の位置にする（`uncMs = 500`）。
4. 逆向きには使わない（型から遠いという理由で、はっきりした射を消さない）。射には `typicality`（距離 / 上の上限）を付けるだけ。

**拾い直した候補を射数に入れない理由**（下書きの 4.9 との違い）: 型が合うことは「引いて、保持して、腕を下ろした」流れが射に似ていることしか
言わず、離れの位置は決まらない。独立したベンチマークで `likely` が付いた候補 20 件のうち、18 件は本当に射だったが、型の位置が
真の離れの ±150ms に入ったのは 7 件だけだった（種 1〜5、core・sensitivity・behaviour）。オーナーの決定（1 章）に従い、射数には入れず、
画面で「射かもしれません」として先に出す材料にする。

## 5. 射ごとの値と不確かさ

### 5.1 窓

射の値は、離れの `[FEAT_FROM_MS (600), FEAT_TO_MS (60)]` 前の窓の **中央値**（事象用の系列）。保持が短ければ、アンカーより前へは

### 5.3 測定のゆれ（`captureNoise`）

項目ごとに、**その回の保持の中で、同じ幅の窓を離れからさかのぼって並べ、隣り合う窓の中央値の差** からゆれを見積もる。

```text
射 k の窓の中央値: m_k0（離れの直前。その射の値）, m_k1, m_k2, …（アンカーの 200ms あとまで、最大 FEAT_WINS_MAX (8) 個）
間隔 L = 1..NOISE_LAGS (3) について   σ_L = sqrt( 平均_{k, j} (m_k(j+L) − m_kj)² / 2 )
σ = L についての最大値、 自由度 ν = その L で使った差の個数（4 個未満の L は使わない）
```

- Allan 分散と同じ形で、「窓 1 個ぶんの中央値が、時間をおいて測り直すとどれだけ変わるか」を測る。
- 窓の中の散らばり（ブロックの標準誤差）を使う案は捨てた。ランドマークのずれは数百 ms かけてゆっくり動くので、窓の中の
  散らばりはそれを見落とす。下書きのその版は、雑音だけの回の 45〜50% に「違う射」の印を付けた。
- 保持中の本当の動き（狙いのゆれ、伸び合い）もゆれに入る。つまり **大きめに見積もる側** に倒れる。印が減る方向なので受け入れる。
- 時間の項目は別に決める: 離れの時刻は `releaseUncMs`、アンカーは定義のあいまいさを含めて ±100ms（7 章の 95% 値）。
  `holdMs` のゆれは `sqrt(100² + releaseUncMs²)`。
- 見えないゆれ: 保持の長さ（数秒）より長く続くずれ。たとえば袖のしわで手首の点が 1 射ごとに違う位置へ寄る、といったずれは、
  この方法では本当の違いと区別できない（7.3 の「ずれの続く長さ 約 3 秒」）。画面の「見えないもの」に書く。

### 5.4 射どうしの比較（`compareShots`）

射が 4 本以上のとき、項目 `f`・射 `k` について、

```text
Δ = x_k − (ほかの射の中央値)
u = σ_f · sqrt(1 + (π/2)/(n − 1))            自分の値のゆれと、ほかの射の中央値のゆれ
印を付ける条件:  |Δ| > t_ν(1 − p/2) · u   かつ   |Δ| > 床_f
p = 1 − (1 − 0.05)^(1/(n · 項目数))           Šidák。1回の記録の中で、雑音だけで印が 1 つでも付く確率を 5% に抑える
```

- `t_ν` は自由度 ν（上限 60）の t 分布の分位点（Cornish–Fisher 展開。ν ≥ 6 で使う。それ未満は印を付けない）。
- 床（これより小さい違いは、ゆれが小さく見積もられても出さない）: 位置 0.03 胴（1.5cm）、`bowElev`・`shTilt` 2°、`elbAng` 4°、`lean` 1.5°、
  時間 0.3 秒。ランドマークそのものの分解能を下回る主張をしないため。
- 6 射・9 項目なら p ≈ 0.00095、ν = 30 で分位点は約 3.7、`u ≈ 1.15σ`。つまり **ゆれの約 4.2 倍** を超えた違いだけが出る。
- 印は「測定のゆれより大きい違い」という測定についての主張で、「外れ値」「悪い射」とは言わない。射手のふだんのばらつきと
  比べた検定は、6 射では力が無いのでしない。
- 項目ごとの要約: 中央値、射どうしの標準偏差 `spread`、ゆれ `noise`、ゆれを除いたばらつき `sqrt(max(0, spread² − noise²))`。
  `spread² / noise² < F_{0.95}(n − 1, ν)` のときは「ばらつきは測定のゆれと区別できません」と出す（6 射・ν = 30 なら `spread < 1.59·noise`）。
- 標準偏差そのものの不確かさ: 6 射なら 95% 区間は 0.62〜2.45 倍（χ²。`grouping-stats-v3.md` と同じ式）。画面に倍率で書く。

### 5.5 重ね図用の姿（`poseHold`、`poseRel`）

記録からあとで重ね図を描けるように、射ごとに 2 つの姿を返す（オーナーの決定、2026-11-14: 保存する）。

```text
poseHold = 保持の姿: 特徴と同じ窓（離れの [600, 60] ms 前）の、点ごとの中央値
poseRel  = 離れたあとの姿: 離れの [POSE_REL_FROM_MS (150), POSE_REL_TO_MS (350)] あとの、点ごとの中央値（射だけ。引き戻しは null）
どちらも [鼻x, 鼻y, 弓手の肩x, y, 引き手の肩x, y, 弓手の肘, 引き手の肘, 弓手の手首, 引き手の手首, 弓手の腰, 引き手の腰] の 18 個の整数
  （FormAnalyze.ROLES の順）。正準座標（原点 = 両肩の中点、弓の向きが x 正、上が y 正）を 0.01 胴に丸めたもの。見えなかった点は null
```

- 記録（design.md 5.1）の `ps`・`pr` には、この配列をそのまま入れる。1 射あたり JSON で約 110〜130 バイト（2 つ合わせて）。
- 列（時系列）ではなく、1 射につき 2 つの時刻の中央値だけである。映像・画素・ランドマークの列は保存しない。
- 描くときは、`quality.dir`（弓が画面の右か左か）で左右を戻す。弓の向きを x 正にそろえてあるので、右利きと左利き、
  胸側と背中側の記録を同じ向きに重ねられる。
- 補完した点（3.3 の 7）は入れない（見えなかった点は null のまま）。

### 5.6 cm に直すとき（解析器の外で）

解析器は胴の長さの単位のまま返す。cm の目安を出すのは画面の役目で、設定に身長 `H`（cm）があるときだけ、次の式で直す。

```text
胴の長さ（cm）≈ 0.288 × H          両肩の中点 〜 両腰の中点。肩の高さ 0.818H − 大転子の高さ 0.530H（Drillis & Contini 1966）
値（cm）≈ 値（胴）× 0.288 × H       例: H = 170 なら胴 49cm。0.03 胴 ≈ 1.5cm
```

- 0.288 は体節比の平均で、人によって ±4% ほど違う（座高の比の個人差）。MediaPipe の肩・腰の点は関節の中心の見当で、
  骨の目印とは一致しない。だから cm は「目安」としてだけ出し、±5% 以上の縮尺の不確かさがあると書く。
- 身長が設定されていなければ、cm は出さない（または「胴を 50cm としたとき」と明記する）。
- この比は解析器には持たせない（`FormAnalyze` の中に 0.288 は無い）。画面の側の定数として 1 か所に置き、この節を出典にする。
- 面内の量（`ext`・`ancX`・`relBack`）は、カメラが斜めだと cos で縮む。cm に直しても、斜めの回の値は短く出る（8 章）。

射に数えなかった候補は、`quality` ではなく、いちばん上の `candidates` に入る（1 章）。`opts.debug` を付けると、
区間ごとの判定の中身（終わり方、変わり目、`zL`・`zJ`）が `quality.debug` に入る（診断用。保存しない）。

**置き方の印**:

- `rho` = はっきりした射の `armLen`（弓手の腕の見かけの長さ / 胴の長さ）の中央値。真横なら腕は画面と平行で最も長く写り、
  カメラが射線に対して斜めになるほど cos で縮む。胴の長さは縦なので縮まない。体格の比（真横での値）は人ごとに違うので、
  角度に直さず、**その人の記録どうしで `rho` を比べる**。
- `omega` = `shWidth`（肩幅 / 胴）の中央値。同じ理由で縮む。補助。
- `side` = 胸側（`"c"`）か背中側（`"b"`）。利き手と `dir` で決まる: 右利きで弓が画面の右、または左利きで弓が画面の左なら胸側。
- `cls` = 真横 `"s"` / やや斜め `"o"` / 斜めすぎ `"x"`。基準 `rho_ref` は `opts.rhoRef`（その人の過去の記録の `rho` の最大値。3 件以上あるときに
  画面の側が渡す）、無ければ体格の目安 `RHO_REF (1.15)`（上腕 0.186H + 前腕 0.146H を、肩〜大転子 0.288H で割った値。Drillis & Contini 1966 の体節比）。
  `rho/rho_ref ≥ 0.94` を真横（約 20° 以内）、`≥ 0.77`（約 40° 以内）をやや斜め、それ未満を斜めすぎとする。
  体格の目安しか無いうちは誤差が大きい（独立したベンチマークの真横の場面でも `rho` は 1.1 前後で、目安に対して「やや斜め」と出る回がある）ので、
  画面は「真横に近い」「斜め」とだけ書き、角度は出さない。

## 9. 実射でしか決まらないこと

1. 離れのとき、引き手の手首と肘の点がどれだけ動くか（保持中のゆれの幅の 5 倍・6 倍を超えるか）。`EXIT_MIN`・`EXIT_K`・`LOCATE_K` が決まる。
   独立したベンチマークでは肘が大きく動く（胴の 20〜90%）が、これは合成の射手の作り（二関節の逆運動学）によるもので、実射の肘がこれほど
   動くかどうかは分からない。肘が動かない射手では、手首だけで決めることになり、数え落としが増える。
2. 離れの動きの形（4.6 の「力がかかって動き出す」形）と、その時定数。時刻の偏りがこれで決まる。
3. 弓・弦・アームガード・チェストガード・矢筒が、手首と肩の点をどれだけずらすか。顔の前の引き手の点が安定するか。
   `visibility` が、隠れたときに本当に下がるか（3.3 の 1 はそれを当てにしている）。
4. ランドマークのずれの大きさと続く長さ（7.3、7.5 の注）。数え落としの率、保持の長さの誤差、違いの印の誤りの率がこれで決まる。
5. 弓を下ろしながら引き戻す人と、離れのあと引き手を前へ下ろす人の区別（4.6 の `LETDOWN_FWD`）。
6. 引きの軌道が最小躍度の形にどれだけ近いか（4.8）。当てはまらない射手では、アンカーは速さの差分で決まり、ゆれに弱くなる。
7. iPhone で推論が何 fps 出るか、熱で落ちるか。`requestVideoFrameCallback` の時刻が PWA で正しいか。
8. 門 G1〜G3 の幅（長距離の仰角、アンカーが高い人・低い人、顔の横で引く人）。
9. 人や場面が切り替わったときの `"bodyMoved"`（4.6）が、離れで頭を大きく動かす射手を落とさないか。

### 9.1 オーナーに決めてほしいこと（この段で出てきたもの）

1. **「難しい場面の再現率 ≥ 90%」の読み替え**（7.5 の注）: 候補を含めて数えるか、基準を外すか。
2. **`likely` の候補の扱い**（4.9）: いまは数に入れず、「射数を直す」で先に出す。入れるなら、時刻は粗い（±0.5 秒）と明記することになる。
3. **速射（保持 0.4 秒未満）は数えられない** ことを、画面の「見えないもの」に書くか。
4. **名目のゆれでの未達（射数がぴったり 89%、保持の 95% が 0.47 秒）のまま、実地の確認（design.md 6.3）へ進むか。**
   合成のゆれが現実より大きいのか小さいのかは、実射を 1 回撮れば分かる。

## 10. メモリと計算の量（iPhone）

### 10.1 撮影中に持つもの

1コマ = 13 点（鼻、耳 2、肩 2、肘 2、手首 2、腰 2、膝 2）× (x, y, visibility) の Float32 = 156 バイト、時刻 Float64 = 8 バイト。計 164 バイト。
33 点すべての x, y, z, visibility（536 バイト）は持たない。

| 毎秒コマ数（推論） | 10 分  | 30 分（上限） |
| ------------------ | ------ | ------------- |
| 30                 | 3.0 MB | 8.9 MB        |
| 60                 | 5.9 MB | 17.7 MB       |

- 4,096 コマずつの型付き配列を足していく（途中で作り直さない）。上限は 30 分。上限に来たら撮影を止めて解析へ進む。
- 解析の作業領域は入力の 6 倍ほど（等間隔の系列、事象用、特徴用、信号）。30 分・60fps でも 110MB を超えないよう、実装では
  Float32 を使い、信号は使い終わったら捨てる。10 分・30fps なら 20MB 未満。
- 終わったら、バッファは解析結果と一緒にその画面の間だけ持ち、画面を閉じたら捨てる。保存しない。

### 10.2 計算

- 解析は全体で O(コマ数)。実装で、10.4 分・30fps（18,774 コマ、54 射）が Node で 0.27 秒（`npm run check:form-analyze` が毎回測る。
  基準は 1.5 秒）。下書き（移動中央値を毎回並べ替える素朴な実装）は 8.6 分・30fps で 0.57 秒だった。iPhone でも待ち時間は 1〜2 秒に収まる見込み（実機で測る）。
- 撮影中のおおよその射数: 直近 20 秒（600 コマ）に 1 秒おきに同じ解析をかける（Node で約 11ms）。続けて 4 回、同じ時刻に見つかった射だけを数える（design.md 11.8）。引き尺の水準は前回の値を引き継ぐ。

### 10.3 推論の間隔

- コマの時刻は `requestVideoFrameCallback` の `mediaTime` を使う（iOS 15.4 以降）。`performance.now()` と rAF の組は、
  推論の待ちで時刻がずれる。使えない端末では従来の時刻に戻す。
- 弓を上げていない間（G1 を満たさない）は推論を 10fps に落とし、上げたら全速に戻す。上げてから引き切るまで 1 秒以上あるので、
  切り替えの遅れ（100ms）は問題にならない。発熱と電池を抑える。等間隔への直しは 3.2 が受け持つ。
- 撮影中は骨格を描かない（描画の負荷を推論に回す）。
