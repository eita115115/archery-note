  `tools/form-bench/`（7.2）。実射の映像は一度も使っていない。しきい値の初期値はどれも「合成データで破綻しなかった値」で、

## 1. 契約

```text
analyze(frames, { frame: { w, h }, handedness, fps }) → { shots, quality }

frames      = [{ tMs, landmarks: [33 × { x, y, z, visibility }] | null }]
              tMs は撮影開始からの ms。x, y は MediaPipe の正規化座標（x は幅、y は高さで割った値、y は下向き）。
              landmarks が null のコマは「姿勢が取れなかった」。
frame.w, h  = ランドマークを正規化した画面の大きさ（px）。縦向きなら w < h。
handedness  = "right" | "left"（right = 右手で引く。弓は左手）
fps         = 目安の値。時刻は tMs だけを信じる（間隔が不ぞろいでもよい）。

shots       = [{ releaseMs, anchorStartMs, holdMs, kind: "shot" | "letdown", features, ...追加の項目 }]
              時刻の昇順。射数は kind === "shot" の個数。
quality     = この回の測定の質（6 章）
```

追加の項目（契約を壊さない範囲で足す）:

| 項目                    | 意味                                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------------- |
| `drawStartMs`, `drawMs` | 引き始めの時刻と、引き始めからアンカーまでの時間                                                      |
| `releaseUncMs`          | 離れの時刻の不確かさ（ms）。ふつうは 1コマの 1/4〜1/2、欠測にかかれば欠測の幅の半分                   |
| `weak`                  | true = 離れがはっきり写らなかった射。数には入れるが、時刻は粗い（`releaseUncMs` ≥ 150）               |
| `confidence`            | 0〜1。0.5 未満は画面で「確かめてください」と出す（`weak` の射は 0.4、低い基準で位置を採った射は 0.6） |
| `source`                | 離れを見つけた手がかり: `"draw"`（引き手）/ `"bow"`（弓手の反動）/ `"none"`（腕を下ろす動きから逆算） |
| `kindScore`             | 離れの段差の大きさ（その保持のゆれの幅の何倍か。4.6）                                                 |
| `features`              | 射ごとの値（5 章）。測れなかった項目は null                                                           |
| `wins`                  | 項目ごとの、保持の中の窓の中央値の列（測定のゆれの見積もりに使う。保存しない）                        |

`kind === "letdown"` の行は `releaseMs` に「保持が終わって手が前へ動き始めた時刻」を入れる。`features` は同じ形で返すが、
射どうしの比較には使わない。

決まりごと:

- 純関数。DOM・`db`・時計・乱数を使わない。同じ入力には同じ出力。入力の配列を書き換えない。
- 入力が空・短い（10コマ未満）・体が写っていないときは `shots: []` と `quality.warnings` を返す。例外は投げない。
- 画面の形・左右・大きさ・時刻の原点を変えても結果が変わらない（7.4 の不変性の検査）。

内部の関数（どれも純関数。Node で単体の検査ができる）:

```text
packFrames(frames, opts)             → { t[], pts{名前:{x[],y[]}}, coverage }     3.1 取り込み
resample(packed, fpsHint)            → { dt, t0, n, pts }                         3.2 等間隔にする
buildSignals(resampled)              → sig（体の単位の座標と信号）                3.3 体の単位
holdLevel(sig, 門, still)            → 保持の水準                                 4.3
drawnRuns(sig, level?, still)        → { runs:[[開始, 終了]], level }             4.3 引いている区間
terminalEvent(sig, 止まった位置, 区間の終わり, 次の区間) → { kind, t, unc, weak, … } | null   4.5・4.6
qStat(sig, 点, から, まで, 軸?)      → { q[], th, thNeg, med, lowSpread }         4.6
onsetFit(sig, 点, 基準, 位置)        → { t, unc, tau }                            4.6 動き始めの時刻
anchorStart(sig, 離れ, 基準, ゆれ, still) → 位置                                  4.8
shotFeatures(sig, 離れ, アンカー, 基準)   → { f, wins }                            5
captureNoise(射の配列)               → { noise, df }                              5.3
compareShots({shots, quality}, opts) → { n, features, flags }                     5.4
analyzePacked(packed, opts)         = 2〜5 を通したもの（撮影中のバッファから直接呼ぶ）
analyze(frames, opts)               = analyzePacked(packFrames(frames, opts), opts)
```

## 2. なぜ「あとでまとめて」か

いまの仕組みは、1コマごとに状態を進める実時間の状態機械で、しきい値はすべて手で決めた固定値である。
監査（AUDIT.md）にある失敗は、ほぼこの作りから出ている。

| いまの失敗                                       | 原因                                                  | まとめて解析すると                                                                             |
| ------------------------------------------------ | ----------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 縦向きで 0射（アンカー圏に入らない）             | 画面の形に依存する固定のしきい値                      | 画素で測り、胴の長さで割る。しきい値はその回の分布から決める                                   |
| 6射のうち 4射を落とす                            | 発射の速さ 9 胴/秒 に届かない、保持の条件を満たさない | 先に「手を前へ戻さずに腕を下ろした」ことで射と決め、離れの位置はその保持自身のゆれと比べて探す |
| 16 回の発射のうち 13 回を捨てる                  | 発射のあと 400ms で取り消しを決める                   | 離れのあと 0.5 秒以上の動きまで見てから、射か引き戻しかを決める                                |
| 引き切りの肘の角度が 125° を超えない             | 画像の上の角度を、立体の角度のつもりで門にしていた    | 肘の角度を門に使わない。使うのは手首・肩・鼻の位置だけ                                         |
| ドリフトのしきい値がランドマークのゆれより小さい | ゆれを測っていない                                    | 回ごとに測定のゆれを見積もり、それより大きい違いだけを出す                                     |
| 追跡が切れると橋渡しの特例（NB/NB2）が要る       | 先が見えないので、その場で決めるしかない              | 欠測の前後を両方見て、短い欠測は補間、長い欠測は「見えなかった」として扱う                     |

実時間で要るのは、置き方の案内と、撮影中のおおよその射数だけになる。射数は、同じ解析器を直近 20 秒に 2 秒おきに
かけて出す（別の状態機械を持たない）。終わったあとの解析が正で、撮影中の数は「目安」と明記する。

検討して採らなかった案:

- **動画を丸ごと取っておき、あとで全コマを推論する**: 60fps の全コマと重いモデルが使えるが、10 分の動画（約 190MB）を
  メモリに持ち、推論に数分かかる。射場で待てない。保存済み動画の解析（撮影とは別の入口）にだけ使う。
- **学習済みの分類器で射を見分ける**: 実射の教師データが無く、オーナーの映像を fixture にしない方針とも合わない。
- **MediaPipe の z（奥行き）を使う**: 1台のカメラからの推定で、手首の z は誤差が大きい。検出にも特徴にも使わない。

## 3. 座標と信号

### 3.1 取り込み（`packFrames`）

- 時刻順に並べ、同じか戻る時刻のコマは捨てる。
- 使う点は 9 つ: 鼻(0)、肩(11, 12)、肘(13, 14)、手首(15, 16)、腰(23, 24)。残りは読まない
  （耳 7, 8 と膝 25, 26 は予備。10.2 のメモリの見積もりには入れてある）。
- 点を使う条件: 値が有限、`visibility ≥ V_MIN (0.3)`、x と y が −0.2〜1.2。満たさない点は欠測。
  いまの 0.5 より低いのは、あとで外れ点の除去と平滑をかけるため。
- **正方形の画素にする**: `X = x·w`、`Y = y·h`。以後、距離と角度はすべてこの座標で測る。
  段A の「16:9 の基準座標」は検出のしきい値を動かさないための選択だったので、v2 では使わない。
- **利き手**: 右利きは 弓手 = 左(11, 13, 15, 23)・引き手 = 右(12, 14, 16, 24)。左利きは入れ替える。
- `coverage` = 姿勢が取れたコマの割合。

### 3.2 等間隔にする（`resample`）

- 間隔 `dt` = コマ間隔の中央値（1000/60〜100ms に収める）。時刻 `t0 + g·dt` の格子へ、点ごと・軸ごとに線形補間する。
- 前後の有効な標本の間が `GAP_FILL_MS (200)` 以下（かつ 1.5·dt 以上のときはその値）なら補間し、それより長ければ欠測（NaN）のまま。
- 撮影中に推論の間隔を変えても（10.3）、ここで同じ間隔になる。

### 3.3 体の単位（`buildSignals`）

1. 外れ点の除去: 各座標に Hampel フィルタ（前後 `HAMPEL_HALF (2)` 標本、中央値から `HAMPEL_K (3)` × MAD を超えたら中央値に置き換える）。
   1コマだけ跳ぶ点を消し、段差（離れ）は残す。**これが「事象用」の系列**で、これ以上は平滑しない。
2. 胴の長さ `T(t)` = 両肩の中点と両腰の中点の距離（px）を、幅 `SCALE_WIN_MS (2000)` の移動中央値にしたもの。取れないコマは回全体の中央値 `T0`。
   コマごとの値で割ると、肩と腰のゆれがすべての値に乗る（いまの仕組みの問題）。2 秒の中央値なら、立つ位置が変わったときだけ追従する。
3. 弓の向き `dir` = 「弓手の手首 − 引き手の肩」の x の中央値の符号（0.6·T0 より離れているコマだけ）。+1 なら弓は画面の右。
4. **正準座標**: 原点 = 両肩の中点、x = `dir·(X − 肩中点X)/T`（弓の向きが正）、y = `−(Y − 肩中点Y)/T`（上が正）。単位は「胴の長さ」。
   左利き・背中側からの撮影は、ここで右利き・胸側と同じ形になる。体ごとの動き（重心のゆれ、カメラのゆれ）は原点と一緒に消える。
5. 信号（どれも胴の長さの単位）:

| 記号              | 定義                                                                                                                      | 使いみち                               |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| `d`               | 弓手の手首と引き手の手首の距離                                                                                            | 引き尺の目安。引いている区間、引き戻し |
| `e`               | 弓手の手首の高さ − 弓手の肩の高さ                                                                                         | 弓を上げているか                       |
| `ay`              | 引き手の手首の高さ − 鼻の高さ                                                                                             | 引き手が顔の高さにあるか               |
| `p`               | 引き手の手首の位置（正準座標）                                                                                            | 離れ、アンカー                         |
| `r`               | 弓手の手首の位置（正準座標）                                                                                              | 離れ（弓手の反動）、弓手の下がり       |
| `ds, es, ays, ps` | 上の「特徴用」の平滑（幅 `SMOOTH_MED_MS (100)` の中央値 → 幅 `SMOOTH_AVG_MS (160)` の平均。前後対称なので時刻がずれない） | 区間の判定、アンカー                   |
| `vs`              | `ps` の速さ（前後 1 標本の中心差分、胴/秒）                                                                               | 手が止まったか                         |

平滑を 2 本に分ける理由: 時刻は平滑でなまる（160ms の平均は段差を 160ms に広げる）。区間の判定は平滑した系列で、
時刻は事象用の系列で決める。

## 4. 射と引き戻しを見つける

### 4.1 考え方

射の 1 周期は、1 本の信号 `d`（手首どうしの距離）に大きく出る。セットアップで約 0.4、引き切りで約 1.4〜1.6（真横）、
つまり雑音（0.01〜0.03）の数十倍の振れ幅がある。引き切りの水準は同じ射手なら毎回ほぼ同じなので、
**その回の分布から水準を決められる**。

保持の終わり方は 2 つしかない。

- **離れ**: 引き手が後ろ（弓と反対の向き）へ急に動き、弓手も反動で動く。手首どうしは近づかない。
- **引き戻し**: 弓を上げたまま、引き手が前（弓の向き）へ戻り、手首どうしが近づく。

速さの大きさは使わない。使うのは **手首どうしが近づいたか**・**弓手が下がったか**（終わり方）と、引き手が **後ろへ** 動いた段差（離れの位置）で、
どれも置き方に依らず符号が変わらない。順番は「終わり方を先に決め、離れの位置をあとで探す」。雑音が大きいとき、離れの段差だけを
頼りにすると見落とすが、「手を前へ戻さずに腕を下ろした」ことは大きな動きなので見落としにくい。

### 4.2 構えの門（置き方に強い 2 条件）

```text
G1: G1_LO (−0.45) ≤ es ≤ G1_HI (+0.7)     弓手の手首が、弓手の肩とほぼ同じ高さ（長距離の仰角を許す）
G2: G2_LO (−0.65) ≤ ays ≤ G2_HI (+0.3)    引き手の手首が、鼻より少し下〜顔の高さ
```

どちらも **高さだけ** の条件である。カメラが斜めでも、縦の長さはほとんど縮まない（横の長さは cos で縮む）ので、置き方で変わりにくい。
矢取り、弓を持って歩く、弓を片手で上げる、といった場面は、どちらかを満たさない。

### 4.3 保持の水準と、引いている区間（`holdLevel`、`drawnRuns`）

1. G1・G2 を満たし、引き手が止まっている（`vs < still`。4.4）コマの `ds` を集める。止まっている所は、セットアップ・保持・
   離れのあとの残身の 3 か所にかたまる。
2. 幅 `LEVEL_BIN (0.05)` のヒストグラムで、隣り合う 3 つの合計が極大になる所を「かたまり」とする。使うのは、いちばん大きい
   かたまりの `LEVEL_MASS (25%)` 以上の時間があり、250ms 以上で、`D_MIN (0.55)` 以上のものだけ。
3. **保持の水準 `level`** = いちばん高いかたまりの `LEVEL_REL (0.55)` 倍以上で、いちばん低いかたまりの中央値。
   残身は保持より引き尺が長く、セットアップはずっと短い。該当が無ければ射なし（`warnings: "noFullDraw"`）。
4. しきい値 = `max(D_MIN, D_FRAC (0.8) × level)`。G1・G2 を満たし `ds` がしきい値以上のコマの連なりを区間とする。
   途切れは `RUN_BRIDGE_MS (250)` まで橋渡しし、`RUN_MIN_MS (300)` より短い区間は捨てる。区間には残身も入る。

`D_MIN` の 0.55 は「手首どうしが胴の長さの半分強は離れている」という意味で、真横なら引き切りの 4 割、50° 斜めでも 6 割にあたる。

捨てた版: 水準を「G1・G2 を満たすコマの `ds` の 97% 点」にしていた。離れで引き手が大きく後ろへ抜ける射手では 97% 点が残身の
水準になり、区間が離れのあとから始まった。独立したベンチマーク（7.2）の雑音なしの場面で 18 射中 6 射しか合わず、気づいた。

### 4.4 手が止まった位置

- 静止の速さ `still` = `clamp(STILL_K (3) × vs の 20% 点, STILL_MIN (0.2), STILL_MAX (0.8))` 胴/秒。
  ランドマークのゆれが大きい回は自動で上がる。下限 0.2 は、胴 50cm なら 10cm/秒。
- 区間の中で、`vs < still` が `SETTLE_MS (150)` 続いた最初の位置を「手が止まった」とする。無ければ区間の先頭。
- 保持の終わりは、そこから `REF_FROM_MS (400)` あと（基準の窓ひとつぶん）より先で探す。引き終わりの最後の数 cm を
  「後ろへの動き」と取り違えないため。**保持が 0.4 秒より短い射は、はっきりした離れとしては拾えず、4.6 の「弱い射」になる。**
- 保持の始めの水準: 止まってから `HOLD0_MS (1000)` の `ds` の中央値 `D0`、弓手の高さ `es` の中央値 `e0`、それぞれのゆれ（MAD）。

### 4.5 終わり方を、大きな動きで決める（`terminalEvent` の前半）

止まった位置から、区間の終わり + `LOOK_MS (2500)`（次の区間の手前まで）へ向かって、最初に起きたものを取る。

| 起きたこと                                                              | 種類      |
| ----------------------------------------------------------------------- | --------- |
| 手首どうしが近づいた（`ds ≤ D0 − closeTh`）とき、弓手はまだ上がっている | `"close"` |
| 弓手が下がった（`es ≤ e0 − dropTh`）。近づくのと同時でもこちら          | `"lower"` |
| `RUN_BRIDGE_MS` を超えて見えなくなった                                  | `"gap"`   |
| どれも起きないまま終わった                                              | `"end"`   |

```text
closeTh = max(CLOSE_FRAC (0.12) × D0, MACRO_K (5) × ds のゆれ)
dropTh  = max(ARM_DROP (0.15),        MACRO_K (5) × es のゆれ)
どちらも、その時点から SUSTAIN_MS (300) の中央値でも超えていること
```

引き戻しは弓を上げたまま弦を戻すので、近づくほうが先に起きる。射のあとに腕を下ろすときは、下がるほうが先か同時に起きる。
しきい値を保持の始めのゆれから決め、300ms 続くことを求めるのは、ランドマークのゆれで「近づいた」「下がった」と取り違えないため
（固定の 0.1 と 1 コマの判定だった版は、独立したベンチマークで保持の途中に引き戻しや腕下ろしを見つけてしまった）。

### 4.6 離れの位置と時刻（`qStat`、`onsetFit`）

終わり方が決まったら、その手前で **引き手がいちばんはっきり後ろへ動いた所** を探す。

```text
引きの軸 û = 保持の始めの、弓手の手首 → 引き手の手首 の向き（後ろが正）
q(i) = ( 直後 Q_POST_MS (200) の中央値 − 直前 [REF_FROM_MS (400), REF_TO_MS (60)] ms の中央値 ) · û
ゆれの幅 s = min(q の中央値 − 16% 点, 84% 点 − 中央値)       事象の少ない側から取る
はっきりした離れ:  q の最大 ≥ max(EXIT_MIN (0.03), 中央値 + EXIT_K (6) × s)
位置として採る:    q の最大 ≥ max(EXIT_MIN,        中央値 + LOCATE_K (3.5) × s)
```

- `q` は「いま、少し前の位置から、後ろへどれだけ動いたか」。向きを決めた 1 次元の量にするのは、軸と直角の向きのゆれを
  捨てるため（動いた距離そのものを使う版は、ゆれが大きい場面でしきい値が離れの段差を超えた）。
- しきい値は **その保持の中の `q` 自身の分布** から決める。固定の速さや距離を使わない。
- 弓手の手首にも同じ量（こちらは動いた距離）を作る。引き手がほとんど動かない離れを、弓手の反動で見つけるため。

終わり方と合わせて決める:

| 終わり方    | 引き手の `q` の最大                   | 結果                                                                                                                                                                                             |
| ----------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| close 以外  | `EXIT_K` 以上                         | **射**。時刻は下の当てはめ                                                                                                                                                                       |
| close       | 近づく 150ms 前までに `EXIT_K` 以上   | **射**（離れのあと、弓手を上げたまま引き手を下ろした）                                                                                                                                           |
| close       | それ未満                              | **引き戻し**。時刻は `ds` が下がり始めた所（`releaseUncMs = 150`）                                                                                                                               |
| lower / end | `LOCATE_K` 以上                       | **射**。時刻は当てはめ、`releaseUncMs = LOCATED_UNC_MS (60)`、`confidence 0.6`                                                                                                                   |
| lower       | それ未満、弓手の `q` が `EXIT_K` 以上 | **弱い射**（`weak: true`、`source: "bow"`、`releaseUncMs = 150`）                                                                                                                                |
| lower       | どちらも未満                          | **弱い射**（`source: "none"`）。時刻 = 腕を下ろし始めた時刻 − その回のはっきりした射の「弓手を上げていた時間」の中央値（無ければ `FOLLOW_DEFAULT_MS (800)`）、`releaseUncMs = LATE_UNC_MS (500)` |
| end         | `LOCATE_K` 未満                       | 射に数えない。`quality.candidates` に `"noExit"`                                                                                                                                                 |
| gap         | `EXIT_K` 未満                         | 射に数えない。`"noExit"`                                                                                                                                                                         |

「射だと分かっているときは、低い基準（3.5）で位置を採る」のが要点である。腕を下ろした（手を前へ戻していない）ことが射の証拠で、
`q` は「その中のどこか」を決めるだけなので、最大の所を採ればよい。

**弱い射を捨てない理由**: オーナーの困りごとは数え間違いである。離れがはっきり写らなくても、「引いて、保持して、手を前へ戻さずに
腕を下ろした」なら射である可能性が高い。数に入れ、画面で「離れがはっきり写らなかった射」として確かめてもらう。
逆に、弓を下ろしながら引き戻す人は弱い射と区別がつかない。ここは実射で確かめる（9 章）。

**動き始めの時刻**（1コマより細かく）: 保持の基準（その位置の直前 [400, 60] ms の中央値）からの距離 `dev(t)` に、
「一定 → 直線で増える → 一定」の形を当てはめる。

```text
dev(t) ≈ base                               (t < tr)
         base + (top − base)·(t − tr)/tau   (tr ≤ t ≤ tr + tau)
         top                                (t > tr + tau)
base = 候補より前の dev の中央値、top = 候補 + 300ms 以降の dev の中央値
tr を dt/8 刻み、tau を FIT_TAUS (35, 70, 105, 140 ms) から選び、[候補 − 250ms, 候補 + 450ms] の残差二乗和が最小の組
```

しきい値を越えた時刻を取るやり方は、越える前のゆれに引きずられる（下書きの最初の版は 95% で 91ms ずれた）。形の当てはめは
前後の全部の標本を使う。`releaseUncMs` = `max(dt/4, 動き始めにかかる欠測の幅/2)`。

事象どうしは `REFRACTORY_MS (1500)` 以上あける（矢をつがえて引くまでに数秒かかる）。同じ区間で事象は 1 つ。

### 4.7 追跡が切れたとき

- 200ms 以下の欠測は補間ずみ。離れのぶれで引き手の手首が 100ms 消える場面は、合成で 240/240 を数え、時刻の 95% は 37ms だった（7.1）。
- 終わり方が `"gap"`・`"end"` で離れが見つからないとき: `quality.candidates` に `{ tMs, reason: "noExit" }` を残す。射には数えない。
  画面は「見えなかった区間」として出し、利用者が射として足せる。
- **弓手の手首・引き手の手首が保持の途中から見えない**（弓や腕や顔で隠れる）: 下書きは扱えていない（7.1・7.2）。
  実装では次の「補完」を入れる。
  - その回で見えている保持のコマから、肘 → 手首のベクトルの中央値（正準座標）を覚える。
  - 手首が欠測で肘が見えているコマは、手首 = 肘 + そのベクトル とする。補完したコマには印を付け、
    特徴の計算には使わない（検出にだけ使う）。
  - 鼻が見えないときは、鼻の高さ = 両肩の中点 + その回の中央値の差。
  - 引き手の手首の `q` に、引き手の肘の `q` を足した量でも同じ判定をする（手首が顔の前でゆれるとき、肘は安定している）。
- 人が入れ替わった・横切った: 腰の中点が 200ms 以内に `IDENTITY_JUMP (1.0)` 以上動いたら、そこに欠測を入れる（区間を切る。下書きには未実装）。

### 4.8 アンカーに入った時刻と引き始め

定義を先に決める。**アンカーに入った時刻 = 引き終わりに、引き手の速さが `still` を下回り続けた最初の時刻**（「手が止まった」）。

1. 離れからさかのぼり、引き手が保持の基準から `far = max(ANCHOR_FAR (0.08), 2·ANCHOR_K (5)·保持中のゆれ)` より遠かった最後の時刻を探す
   （`ANCHOR_BRIDGE_MS (250)` 以下の外れは無視）。
2. そこから先で、`vs < still` が `SETTLE_MS (150)` 続いた最初の時刻。止まらないまま離したときは 1 の時刻。

「保持位置から 2cm 以内に入った時刻」という位置だけの定義は、保持中のゆっくりしたゆれで途中から切れた
（下書きの版で、保持の誤差の 95% が 2 秒を超えた）。速さの定義にしてからは 95% で約 0.1 秒（7 章）。

引き始め = アンカーからさかのぼって、`ds` が「直前 4 秒の最小値 + 15%」を下回る最後の時刻。`drawMs` = アンカー − 引き始め。

**ベンチマークへの注意**: 正解のアンカーは同じ定義で作ること（引き終わりに、引き手の速さが 0.2 胴/秒を下回る時刻）。
保持の長さは定義でいくらでも変わる量なので、定義を合わせない比較には意味がない。

### 4.9 自己相似で弱い候補を拾い直す（下書きには未実装）

はっきりした射が 3 本以上あるとき、その回の「型」を作って、落とした候補を見直す。

1. 型 = はっきりした射の、離れの前 2.0 秒〜後 0.6 秒の `ds/D`・`es`・`ays` の、時刻ごとの中央値。
2. `quality.candidates`（"noExit"、"unobservedAfter"、短すぎて捨てた区間）のそれぞれについて、見えている標本だけで型との
   正規化した距離（項目ごとに、はっきりした射の型からの距離の中央値で割る）を出す。
3. 距離が「はっきりした射を 1 本ずつ抜いて測った距離の最大値 × 1.5」以下で、見えている標本が型の長さの 50% 以上なら、
   **射（`weak: true`、`confidence: 0.4`）** に格上げする。時刻は型を当てた位置。
4. 逆向きには使わない（型から遠いという理由で、はっきりした射を消さない）。型から遠い射には `flags: "atypical"` を付けるだけ。

これは数え落としを減らすための段で、時刻と特徴は出さない（`features` は null）。

### 5.3 測定のゆれ（`captureNoise`）

項目ごとに、**その回の保持の中で、同じ幅の窓を離れからさかのぼって並べ、隣り合う窓の中央値の差** からゆれを見積もる。

```text
射 k の窓の中央値: m_k0（離れの直前。その射の値）, m_k1, m_k2, …（アンカーの 200ms あとまで、最大 FEAT_WINS_MAX (8) 個）
間隔 L = 1..NOISE_LAGS (3) について   σ_L = sqrt( 平均_{k, j} (m_k(j+L) − m_kj)² / 2 )
σ = L についての最大値、 自由度 ν = その L で使った差の個数（4 個未満の L は使わない）
```

- Allan 分散と同じ形で、「窓 1 個ぶんの中央値が、時間をおいて測り直すとどれだけ変わるか」を測る。
- 窓の中の散らばり（ブロックの標準誤差）を使う案は捨てた。ランドマークのずれは数百 ms かけてゆっくり動くので、窓の中の
  散らばりはそれを見落とす。下書きのその版は、雑音だけの回の 45〜50% に「違う射」の印を付けた。
- 保持中の本当の動き（狙いのゆれ、伸び合い）もゆれに入る。つまり **大きめに見積もる側** に倒れる。印が減る方向なので受け入れる。
- 時間の項目は別に決める: 離れの時刻は `releaseUncMs`、アンカーは定義のあいまいさを含めて ±100ms（7 章の 95% 値）。
  `holdMs` のゆれは `sqrt(100² + releaseUncMs²)`。
- 見えないゆれ: 保持の長さ（数秒）より長く続くずれ。たとえば袖のしわで手首の点が 1 射ごとに違う位置へ寄る、といったずれは、
  この方法では本当の違いと区別できない（7.3 の「ずれの続く長さ 約 3 秒」）。画面の「見えないもの」に書く。

### 5.4 射どうしの比較（`compareShots`）

射が 4 本以上のとき、項目 `f`・射 `k` について、

```text
Δ = x_k − (ほかの射の中央値)
u = σ_f · sqrt(1 + (π/2)/(n − 1))            自分の値のゆれと、ほかの射の中央値のゆれ
印を付ける条件:  |Δ| > t_ν(1 − p/2) · u   かつ   |Δ| > 床_f
p = 1 − (1 − 0.05)^(1/(n · 項目数))           Šidák。1回の記録の中で、雑音だけで印が 1 つでも付く確率を 5% に抑える
```

- `t_ν` は自由度 ν（上限 60）の t 分布の分位点（Cornish–Fisher 展開。ν ≥ 6 で使う。それ未満は印を付けない）。
- 床（これより小さい違いは、ゆれが小さく見積もられても出さない）: 位置 0.03 胴（1.5cm）、`bowElev`・`shTilt` 2°、`elbAng` 4°、`lean` 1.5°、
  時間 0.3 秒。ランドマークそのものの分解能を下回る主張をしないため。
- 6 射・9 項目なら p ≈ 0.00095、ν = 30 で分位点は約 3.7、`u ≈ 1.15σ`。つまり **ゆれの約 4.2 倍** を超えた違いだけが出る。
- 印は「測定のゆれより大きい違い」という測定についての主張で、「外れ値」「悪い射」とは言わない。射手のふだんのばらつきと
  比べた検定は、6 射では力が無いのでしない。
- 項目ごとの要約: 中央値、射どうしの標準偏差 `spread`、ゆれ `noise`、ゆれを除いたばらつき `sqrt(max(0, spread² − noise²))`。
  `spread² / noise² < F_{0.95}(n − 1, ν)` のときは「ばらつきは測定のゆれと区別できません」と出す（6 射・ν = 30 なら `spread < 1.59·noise`）。
- 標準偏差そのものの不確かさ: 6 射なら 95% 区間は 0.62〜2.45 倍（χ²。`grouping-stats-v3.md` と同じ式）。画面に倍率で書く。

## 6. `quality`

| 項目                 | 意味                                                                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `frames`, `coverage` | コマ数、姿勢が取れた割合                                                                                           |
| `fps`, `durationMs`  | 実測の毎秒コマ数（1000/dt）、長さ                                                                                  |
| `scalePx`            | 胴の長さ（px）。100 未満は `warnings: "small"`                                                                     |
| `dir`                | 弓の向き（+1 = 画面の右）                                                                                          |
| `drawLevel`, `still` | その回で決まった引き尺の水準と静止の速さ（しきい値を画面と診断に出せるように）                                     |
| `noise`, `noiseDf`   | 項目ごとの測定のゆれと自由度（5.3）                                                                                |
| `view`               | `{ rho, omega, side, cls }`（下）                                                                                  |
| `candidates`         | 射に数えなかった候補 `[{ tMs, reason }]`。画面で利用者が射として足せる                                             |
| `warnings`           | `"tooShort"`、`"noBody"`、`"noFullDraw"`、`"small"`、`"lowFps"`（15 未満）、`"gappy"`（coverage < 0.8）、`"steep"` |

**置き方の印**:

- `rho` = はっきりした射の `armLen`（弓手の腕の見かけの長さ / 胴の長さ）の中央値。真横なら腕は画面と平行で最も長く写り、
  カメラが射線に対して斜めになるほど cos で縮む。胴の長さは縦なので縮まない。体格の比（真横での値）は人ごとに違うので、
  角度に直さず、**その人の記録どうしで `rho` を比べる**。
- `omega` = `shWidth`（肩幅 / 胴）の中央値。同じ理由で縮む。補助。
- `side` = 胸側（`"c"`）か背中側（`"b"`）。利き手と `dir` で決まる: 右利きで弓が画面の右、または左利きで弓が画面の左なら胸側。
- `cls` = 真横 `"s"` / やや斜め `"o"` / 斜めすぎ `"x"`。基準 `rho_ref` はその人の過去の記録の `rho` の最大値（3 件以上あるとき）、
  無ければ体格の目安 1.15（上腕 0.186H + 前腕 0.146H を、肩〜大転子 0.288H で割った値。Drillis & Contini 1966 の体節比）。
  `rho/rho_ref ≥ 0.94` を真横（約 20° 以内）、`≥ 0.77`（約 40° 以内）をやや斜め、それ未満を斜めすぎとする。
  体格の目安しか無いうちは誤差が大きいので、画面は「真横に近い」「斜め」とだけ書き、角度は出さない。

- 横長と縦長、右と左、胸側と背中側は、同じ値になった（画素で測り、正準座標へ直しているため）。
- 「離れが弱い」は、数は 240/240 で合っているが、時刻はほとんど当たらない。すべて `weak: true` で返り、引き戻しを射に数えた回は無い。
- 「弓手の手首が見えない」は、4.7 の補完を入れていない下書きの値で、扱えていない（206 射と数え、時刻は 3 分の 2 が外れた）。
- 「射の合間に 8 秒いなくなる」の引き戻し 37/40 は、不在の 8 秒に引き戻しが重なった回があるため（写っていないものは返せない）。
- この合成データはゆれが小さい（胴の 1.2%、ずれは約 0.3 秒で入れ替わる）。7.2 のほうが厳しく、現実に近い可能性が高い。

種 1〜5、`npm run bench:form -- --adapter docs/design/form-v2/sketch/bench-adapter.js`）。3 次元の射手をピンホールカメラで写し、

### 7.3 違いの印

縦長・真横・30fps、6 射。雑音だけの回と、4 射目のアンカーの高さだけを下げた回を、同じ乱数で作った（各 200 回）。

| ランドマークのずれの続く長さ | 雑音だけで印が付いた回 | 2cm 下げた | 3cm     | 4cm     | 6cm     |
| ---------------------------- | ---------------------- | ---------- | ------- | ------- | ------- |
| 約 0.3 秒（係数 0.9）        | 0/200                  | 32/200     | 133/200 | 189/200 | 199/200 |
| 約 1 秒（係数 0.97）         | 10/200                 | 42/200     | 121/200 | 179/200 | 199/200 |
| 約 3 秒（係数 0.99）         | 76/200                 | 90/200     | 161/200 | 194/200 | 200/200 |

- ずれが短い（約 0.3 秒）ときは、雑音だけで印が付いた回は 0/200 で、控えめな側に倒れている。4cm の違いは 95%、3cm は 67%、2cm は 16% で見つかった。
  **「アンカーの高さは、3〜4cm より細かい違いは出せない」** が、ゆれの小さい場面でのこの仕組みの分解能である
  （ゆれが大きい 7.2 の条件では、1 射の値そのものが 90% で 4.6cm ずれるので、出せる下限はさらに上がる）。
- ずれが約 1 秒続くと、雑音だけで印が付く回は 10/200（5.0%。95% 区間 2.4〜9.0%）。目標の 5% の境目にある。
- ずれが約 3 秒（保持と同じ長さ）続くと 76/200（38%）。保持の中からは見積もれないゆれで、本当の違いと区別できない（5.3 の「見えないゆれ」）。
  実際のランドマークのずれがどのくらい続くかは、実射の映像でしか分からない。3 秒級のずれが普通に出るなら、床を上げる
  （位置 0.03 → 0.06 胴）か、違いの印を時間の項目だけに絞る。実地の確認（design.md 6.3）のあとで決める。

## 9. 実射でしか決まらないこと

1. 離れのとき、引き手の手首の点がどれだけ動くか（保持中のゆれの 3.5 倍・6 倍を超えるか）。`EXIT_MIN`・`EXIT_K`・`LOCATE_K` が決まる。
2. 弓・弦・アームガード・チェストガード・矢筒が、手首と肩の点をどれだけずらすか。顔の前の引き手の点が安定するか。
3. ランドマークのずれの続く長さ（7.3）。違いの印の誤りの率がこれで決まる。
4. 弓を下ろしながら引き戻す人と、弱い射の区別（4.6）。
5. iPhone で推論が何 fps 出るか、熱で落ちるか。`requestVideoFrameCallback` の時刻が PWA で正しいか。
6. 門 G1・G2 の幅（長距離の仰角、アンカーが高い人・低い人）。

## 10. メモリと計算の量（iPhone）

### 10.1 撮影中に持つもの

1コマ = 13 点（鼻、耳 2、肩 2、肘 2、手首 2、腰 2、膝 2）× (x, y, visibility) の Float32 = 156 バイト、時刻 Float64 = 8 バイト。計 164 バイト。
33 点すべての x, y, z, visibility（536 バイト）は持たない。

| 毎秒コマ数（推論） | 10 分  | 30 分（上限） |
| ------------------ | ------ | ------------- |
| 30                 | 3.0 MB | 8.9 MB        |
| 60                 | 5.9 MB | 17.7 MB       |

- 4,096 コマずつの型付き配列を足していく（途中で作り直さない）。上限は 30 分。上限に来たら撮影を止めて解析へ進む。
- 解析の作業領域は入力の 6 倍ほど（等間隔の系列、事象用、特徴用、信号）。30 分・60fps でも 110MB を超えないよう、実装では
  Float32 を使い、信号は使い終わったら捨てる。10 分・30fps なら 20MB 未満。
- 終わったら、バッファは解析結果と一緒にその画面の間だけ持ち、画面を閉じたら捨てる。保存しない。

### 10.2 計算

- 解析は全体で O(コマ数)。下書き（移動中央値を毎回並べ替える素朴な実装）で、8.6 分・30fps（15,526 コマ）が Node で 0.57 秒、
  60fps（31,051 コマ）が 1.36 秒。実装の目標は 10 分・30fps で 1.5 秒以内。iPhone でも待ち時間は 2〜3 秒に収まる見込み（実機で測る）。
- 撮影中のおおよその射数: 直近 20 秒（600 コマ）に 2 秒おきに同じ解析をかける（約 30ms）。引き尺の水準は前回の値を引き継ぐ。

### 10.3 推論の間隔

- コマの時刻は `requestVideoFrameCallback` の `mediaTime` を使う（iOS 15.4 以降）。`performance.now()` と rAF の組は、
  推論の待ちで時刻がずれる。使えない端末では従来の時刻に戻す。
- 弓を上げていない間（G1 を満たさない）は推論を 10fps に落とし、上げたら全速に戻す。上げてから引き切るまで 1 秒以上あるので、
  切り替えの遅れ（100ms）は問題にならない。発熱と電池を抑える。等間隔への直しは 3.2 が受け持つ。
- 撮影中は骨格を描かない（描画の負荷を推論に回す）。
