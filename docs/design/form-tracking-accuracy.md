# 射型の記録: 測定の正確さ（AN-098 段A）

対象: `scripts/46-form-core.js`（純関数）と `scripts/47-form-view.js`（撮影・保存済み動画の解析）。
実射の映像は使っていない。確認は既存の fixture と合成の時系列だけで行った（実射での確認は AN-001 に残る）。

## 1. 何が起きていたか

MediaPipe の正規化座標は x を画面の幅、y を画面の高さで割った値である。これまでは x と y を
そのまま混ぜて距離と角度を計算していたので、同じ姿勢でも画面の形で値が変わった。

同じ画素の姿勢（`tools/check-form-core.js` の合成の射手。胴体長 240px）での値:

| 画面           | anchorNorm 修正前 → 後 | 検出用 drawArm 修正前 → 後 | 表示の引き手肘 修正前 → 後 |
| -------------- | ---------------------- | -------------------------- | -------------------------- |
| 横長 1280×720  | 0.176 → 0.176          | 38.5° → 38.5°              | 38.5° → 22.6°              |
| 縦長 720×1280  | 0.524 → 0.176          | 12.9° → 38.5°              | 12.9° → 22.6°              |
| 横長・中央固定 | 0.176 → 0.176          | 38.5° → 38.5°              | 38.5° → 22.6°              |
| 縦長・中央固定 | 0.524 → 0.176          | 12.9° → 38.5°              | 12.9° → 22.6°              |

3射の合成時系列（30fps）での検出:

| 画面           | 射数 修正前 → 後 | リリース時刻（ms）修正後 |
| -------------- | ---------------- | ------------------------ |
| 横長 1280×720  | 3 → 3            | 3333, 8033, 12733        |
| 縦長 720×1280  | 0 → 3            | 3333, 8033, 12733        |
| 横長・中央固定 | 3 → 3            | 3333, 8033, 12733        |
| 縦長・中央固定 | 0 → 3            | 3333, 8033, 12733        |

縦長では anchorNorm の最小が 0.433 で、アンカー圏（`CLOSE_IN` 0.35）に一度も入らず、1射も数えなかった。

中央固定（幅の中央 70% を切り出してモデルへ渡す）は、`47-form-view.js` が切り出しの座標を
`x*0.7+0.15` で画面全体の座標へ戻しているので、修正前から全体の画面と同じ値だった。モデルが見る画像の
形は変わるが、計算に使う座標の形は変わらない。これを検査で固定した。

## 2. 決めたこと

### 2.1 基準の座標系（検出に使う）

検出のしきい値（`FORM_PH`）は、すべて 16:9 横長の映像の正規化座標で調整してある
（`tools/golden-replay/sources.md` の映像は 1920×1080 と 1280×720）。そこで基準を
「16:9 横長の正規化座標」と決め、ランドマークの x に次の倍率を掛けてから計算する。

```text
kx = (w * 9) / (h * 16)      w, h = ランドマークを正規化した画面の大きさ（px）
x' = x * kx,  y' = y
```

- 1280×720 と 1920×1080 では kx がちょうど 1 になり、元のランドマークをそのまま使う。値はビット単位で従来と同じ。
- 画面の大きさを渡さない呼び出し（既存の検査、fixture の再生）も kx = 1 で、返すキーも従来のまま。
- 中央固定のときは、ランドマークを画面全体へ戻したあとなので、画面全体の大きさを渡す。
- 基準の座標系は正方形の画素ではない（横が 9/16 に縮んでいる）。しきい値を動かさないための選択で、
  しきい値そのものの見直しは実射のデータ（AN-001）が要る。

### 2.2 表示・保存する肘の角度は正方形の画素で測る

基準の座標系のまま角度を出すと、横長でも実際の画像上の角度と違う値になる（上の表: 画像上 22.6° の
引き手肘が 38.5°）。オーナーの「数値が信用できない」に当たるので、画面の大きさが分かるときは
正方形の画素（x に w/h を掛けた座標）で測った角度を、撮影中の表示・射ごとの値・保存に使う
（`bowArmPx` / `drawArmPx`）。検出は基準の座標系の `bowArm` / `drawArm` を使い続ける。

距離の値（アンカー位置 `anchorNorm`、ドリフト、肩の落ちなど）と score は基準の座標系のままにした。
ラベルのしきい値（アンカーのばらつき 0.045 / 0.08、ドリフト 0.05 / 0.06）がその単位で決めてあり、
画面には比として出るだけで角度のような物理的な読み方をしないため。

### 2.3 1射の肘の角度は、使えるフレームだけの中央値。出せないときは「—」

前腕や上腕がカメラの方を向いて短く写ると、肘の点が数画素動くだけで角度が 0° 付近と 180° 付近を
行き来する（追跡中の fixture で、リリース前後 100ms ほどの間に 3° → 152° → 169° → 0°）。
`formShotArmAngle` は要約窓のフレームのうち次を満たすものだけの中央値を返す（`FORM_ARM`）。

- 上腕・前腕の短いほうが胴体長の 0.2 以上（正方形の画素）
- 肩・肘・手首の visibility が 0.5 以上（値があるとき）
- 使えるフレームが 3枚以上で、その 60% 以上が中央値から ±20° に入る

満たさないときは null を返し、画面は「—」を出す。射そのものは数える。弓手と引き手は別々に判定する。
画面の大きさなしで作ったフレーム（従来の検査）は、従来どおり全フレームの中央値。

0.2・0.5・3枚・60%・±20° は実射で確かめた値ではない。fixture には腕の長さが入っていないので
（保持しているのは anchorNorm・drawArm・bodyScale・conf・引き手手首の1点だけ）、fixture では確かめられない。

### 2.4 `drawArm > 125` の門は変えていない

`adaptiveAnchorFrameUsable` と FULL_DRAW への昇格は `drawArm > 125` を要求する。追跡中の fixture で、
アンカー付近（anchorNorm < 0.65）のフレームのうちこれを通るのは次のとおり。

| fixture                     | アンカー付近 | drawArm > 125 |
| --------------------------- | ------------ | ------------- |
| `oblique-single-release`    | 159          | 41（26%）     |
| `scene-cut-arrow-retrieval` | 397          | 78（20%）     |

fixture は 16:9 横長なので、補正の前後で値は同じ（kx = 1）。つまりこの割合は画面の形のせいではない。
引き切った引き手の肘は、画像の上では肩→肘と手首→肘がほぼ同じ向きになり、角度は小さい（合成の射手で
22.6°、fixture の保持中は 0〜25°）。125° を超えるのは、腕を伸ばしているときか、角度が反転したフレームである。
門をゆるめると検出が変わるので、今回は触っていない。実射のデータで決める（未解決 1）。

### 2.5 ドリフトの端点は両端 100ms の中央値

`formPreReleaseWindow` は、リリース前 0.5 秒（直前 120ms を除く）の最初と最後の1フレームずつを
比べていた。端点を、窓の最初と最後それぞれ 100ms ぶんのフレームの中央値（位置・胴体長・anchorNorm）に
替えた。両端の組は重ならないよう窓のフレーム数の半分まで。2フレームしかない窓は従来と同じ。

しきい値（bow 0.05、draw 0.06、head 0.05）は変えていない。fixture で測った引き手手首の揺れは次のとおりで、
しきい値を決め直す根拠にはならなかった（どちらも射手が小さく写る映像で、胴体長が画面の高さの 13% ほど、
保持中もカメラか体が動いている）。

| fixture                     | 隣り合うフレームの手首の動き（胴体長比）中央値 / 90% | 380ms 窓の drawMove 中央値 2フレーム → 両端の中央値 | しきい値超えの窓   |
| --------------------------- | ---------------------------------------------------- | --------------------------------------------------- | ------------------ |
| `oblique-single-release`    | 0.051 / 0.164                                        | 0.395 → 0.294                                       | 51 → 51（全51）    |
| `scene-cut-arrow-retrieval` | 0.019 / 0.077                                        | 0.134 → 0.092                                       | 237 → 214（全303） |

射手が小さく写ると、1フレームの揺れだけでしきい値を超える。あとで実射から決め直せるよう、端点の組の中での
手首の散らばり（`release.noise`、胴体長比）を射ごとに保存する。判定には使っていない。

### 2.6 矢の判定は、発射前に矢が写っていたときだけ

`judgeArrowCheck` は、確定猶予窓のスコアが低ければ「矢: 発射と一致」としていたので、矢が一度も
写らない映像でもそう出た。発射前のスコアの中央値が `ARROW_PRESENCE.PRESENT_TH`（0.55）以上のときだけ
「発射と一致」「引き戻しの疑い」を返し、それ以外は `unclear`（`reason: "no-arrow-before-release"`）。
撮影画面の射の一覧には「矢: 発射前に写らず判定なし」と出す。発射の検出・取消には従来どおり使わない。

既存の検査のうち1件（発射前のサンプルが無くても `shot-match`）は、直す対象の動作を固定していたので
期待値を `unclear` に替えた。

## 3. 保存する記録

`SCHEMA_VER` も保存キーも変えていない。追加フィールドだけで、旧記録は読み込みで何も変わらない。

```text
formAnalysis.cap = {
  g: 2,                    測り方の版（1 = cap の無い旧記録、2 = 画面の形の補正あり）
  fw, fh,                  ランドマークを正規化した画面の大きさ（px）
  mw, mh,                  モデルへ渡した画像の大きさ（中央固定のときは切り出した幅）
  o: "p" | "l" | "s",      画面の向き
  crop: 0 | 1,             中央固定
  facing: "environment" | "user" | null,   保存済み動画は null
  hand: "right" | "left",
  src: "live" | "replay"
}
features[].release.noise   端点の組の中での手首の散らばり（胴体長比）
```

- 撮影条件は射ごとに控え、保存のときに1記録ぶんへまとめる。途中で変わった項目は `"mixed"`（数値は null）とし `mixed: 1` を付ける。
- 0射の診断用の記録には `cap` を付けない。
- 保存する値は丸める（角度 0.1°、比 0.001、アンカー 0.0001、保持 1ms）。6射の記録は丸める前の約 2.6KB から約 2.3KB になった（目安は約 2KB）。
- 映像・画素・ランドマークの列は保存しない（従来どおり）。

## 4. 比べるのは同じ測り方の記録だけ

`formRecordGeometry(record)` は `cap.g` が 2 以上ならその値、無ければ 1 を返す。版が違う記録は
同じ測定ではないので、次のどれにも混ぜない。

| 場所                                              | 規則                                                     |
| ------------------------------------------------- | -------------------------------------------------------- |
| 詳細シートの前回比（`formRecordInsights`）        | 同じ版の、ひとつ前の記録とだけ比べる                     |
| 一覧の「いつもより」（`formSelfBaselineLabel`）   | 同じ版の、古い記録だけを母集団にする                     |
| 弓手肘の推移（`formTrendMiniHtml`）               | いちばん新しい記録と同じ版だけを描く                     |
| 射型と得点の関係（`formScoreLink`）               | いちばん新しい記録と同じ版だけで分ける。除いた件数を出す |
| 今日の結果のアンカーの副軸（`trAnchorSecondary`） | 紐付いた記録と同じ版の過去の記録だけを基準にする         |

縦向きと横向きの記録は、どちらも版 2 なら互いに比べる（そのための補正）。旧記録どうしはこれまでどおり比べる
（旧記録が縦向きだったかどうかは記録に残っていないので、分けられない）。

## 5. 未解決

1. `drawArm > 125` の門は、横から撮った引き切りの姿勢ではほとんど通らない。FULL_DRAW の表示と adaptive の証拠集めに効いているはず。実射のデータで決め直す（AN-001）。
2. `FORM_ARM` の下限（腕の長さ 0.2 など）は実射で確かめていない。斜めから撮ると引き手肘が「—」になる射が増える可能性がある。
3. ドリフトのしきい値は、射手が小さく写るとランドマークの揺れより小さい。`release.noise` を使って決め直す案がある。
4. 距離の値は基準の座標系（横が 9/16）のまま。正方形の画素へ移すなら、しきい値を実射で決め直す必要がある。
5. 実機（iPhone の Safari）で縦向きのとき `video.videoWidth/Height` が 720×1280 になることは、実機では確かめていない。
