# Field Instrument UI統合 — Record開始画面 設計書

## 目的

Archery NoteのRecord開始画面を、Figmaで比較した3方向（ターゲット中心、条件ログ、静かな開始）の共通点に統合する。既存の採点・保存・用具・サイト・分析データをつなぐ入口として、射場で迷わず毎日使える画面にする。

今回の実装単位は「共通ビジュアル基盤 + Record開始画面」。履歴・分析・サイト・用具は同じ基盤を使う次の小さな画面単位で展開する。

## 現状と課題

- Record開始時に「前回と同じ」「この条件で開始」「履歴」「用具」「条件入力」が同時に強く見え、開始の意思決定が分散している。
- 条件入力が設定フォームのように見え、ターゲット／射場の道具感が弱い。
- helper文とカード面が多く、画面を縮小したときに主役が判別しにくい。
- 既存のターゲットSVG、距離・的・本数、用具スナップショット、前回差分は再利用できる。

現行画面の証拠と比較案は [Figma比較ボード](https://www.figma.com/design/STVrAX3rjNBmkLJNOJL8KB) に置く。

## デザイン方針

一文でいうと、**「墨とインクの精密な計器に、的の色だけを鮮やかに置く」**。

### 3案から統合する要素

1. **Reticle Focus**: ターゲット／レティクルを開始画面の視覚アンカーにする。開始CTAは一つにする。
2. **Range Ledger**: 距離・的・本数・用具を単位付きの条件レールにし、前回値を素早く確認できるようにする。
3. **Quiet Field**: 説明文を削り、条件編集を折りたたみ、余白と静かな前回差分で圧迫感を下げる。

### 色と形

- 背景は現行のクリーンなオフホワイト、文字は墨、補助は灰緑。
- 鮮やかさはターゲット本来の青・赤・黄と、状態を示す緑・青緑に限定する。金は1–2pxのhairline、ドット、または小面積の文字色だけにする。
- 金の塗り、グラデーション、ガラス面、pill、999pxの角丸、カード内カードは追加しない。
- 角丸はボタン8px、入力6px、パネル8px。縦リズムは8pxの倍数、タップ領域は44px以上。
- 見出しは11–12pxのラベル様式。大きく太くするのは主役のCTAとターゲット／主役数値だけ。

## Record開始画面

### 構成

上から次の順に配置する。

1. **微細なセッションヘッダー**
   - 「記録を開始」などの短いラベル。
   - 現在のモード（練習／サイト値）だけを1行で示す。
2. **ターゲットプレビュー**
   - 既存の `targetMarkup()` を使い、選択中の的を小さめの視覚アンカーとして表示する。
   - データ専用色（青・赤・黄）をそのまま使い、外周は墨とhairlineにする。
3. **条件レール**
   - 距離、的、本数、用具を単位付きで横並び／折り返し可能な小さな値ブロックにする。
   - 値の変更操作は既存の `#fDistChips`、`#fFace`、`#fArrows`、`#fSetup` を維持する。見た目だけを整理し、保存形式やイベント契約は変えない。
4. **主CTA**
   - `#fStart` のみを濃い墨面の主CTAにする。
   - 文言は練習モードでは「この条件で開始」、校正モードでは既存の「サイト値つきで開始」を維持する。
5. **前回／条件編集**
   - 「前回と同じ」は主CTAより一段静かなテキストまたはhairlineボタンにする。
   - 「詳しく残す」は折りたたみのまま、日付・ラウンド・サイト・天候などをそこに残す。
   - `recordSetupSnapshot()` の用具・距離情報をCTA直下の静かな1行差分として再利用する。

### 状態

- セッション履歴あり／なし、用具あり／なし、練習／校正、通常幅390px／狭幅360pxを定義する。
- 用具未登録時でも開始CTAは無効化せず、既存の開始フローを維持する。未登録の情報は「未指定」として表示する。
- `prefers-reduced-motion` の現行挙動は変更しない。追加する動きは主CTAまたはターゲット表示の因果を補助するものに限定する。

## 共通ビジュアル基盤

`style.css` の既存トークンを正本として、Record開始画面で必要な静的クラスを整理する。

- `--bg`、`--card`、`--ink`、`--sub`、`--line`、`--line2`、`--green`、`--teal`、`--accent` を再利用する。
- 新しい色を追加する場合は、既存テーマ（light/dark/auto）の意味が一致するセマンティックトークンにする。
- `.launchPanel`、`.recordRepeatBand`、`.sessionCondition`、`.startPrimary`、`.recordDetails` の責務を「面」「値」「主CTA」「詳細」に分け、同じ要素を二重に囲まない。
- 動的な座標、スコア、ターゲット半径、計算済み色はインライン／SVGのままにする。静的な余白・境界・文字サイズのみCSSへ寄せる。

## データフローと不変条件

- `renderRecord()` が算出する `last`、`defSetup`、`defDist`、`defFace`、`defPerEnd`、`mode` をそのまま表示に使う。
- `bindFeatureHint()`、距離・的・本数の既存ハンドラ、`#fStart` の開始処理、`recordSetupSnapshot()` は変更しないか、同じID／`data-testid`を保った最小変更にする。
- 採点・線切り・矢印円の半径、保存／復元、バックアップ／インポート、PWA／Service Worker、バージョン、依存関係は触らない。
- 既存の練習データを削除・移行しない。画面上の表示変更だけで完結させる。

## アクセシビリティ

- 既存のボタンIDとキーボード操作を維持し、状態を表す要素には `aria-pressed`／`aria-expanded` を同期する。
- ターゲットプレビューには「選択中の的、距離、的サイズ」を読み上げられる名前／説明を付ける。
- 補助文は1行に収め、本文14–16px、ラベル11–12pxを下限とする。屋外の明るさを想定し、墨・白・緑のコントラストを確保する。
- 既存のフォーカスリングを壊さず、主CTAと条件編集のフォーカス位置を確認する。

## プロダクトビジョンの4ゲート

1. **既存機能をつなぐ**: Record開始時にスコア条件、用具、サイト値、前回結果を同じ条件レールへ接続する。
2. **成長を見える化する**: 前回からの小さな差分を静かな1行で残す。新しいダッシュボードは追加しない。
3. **完全ローカル**: 表示は既存のローカルDBと純粋関数だけを使い、通信・クラウド推論を追加しない。
4. **毎日使える**: 最短で開始でき、詳細入力は必要なときだけ開く。派手なゲーミフィケーションは追加しない。

## 検証

実装後に次を実行する。

- `git diff --check`
- `npm run check:app`
- `npm run check:ui`
- `npm run lint`
- `npm run test:e2e`
- `npm run check:all`

加えて、390×844、360×780、1280px幅でRecord開始画面を確認する。既存の開始、距離変更、的変更、本数変更、詳しく残す、前回と同じ、記録中への遷移を手動で確認する。

## 実装範囲外

- 履歴／分析／サイト／用具画面のレイアウト変更（次の画面単位で実施）。
- 採点ロジック、フォーム診断、ストレージスキーマ、Service Worker、PWA更新、バージョン、依存追加、GitHub Pages公開。
